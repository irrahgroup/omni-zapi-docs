## API Credentials

{projectName} uses a key pair: **Public Key** and **Secret Key**. Both are generated in the **Security** menu of the dashboard: [Security](https://app.omni.z-api.io/app/security).

---

## Public Key

The Public Key is used by the channel connection SDK ([`@omnizapi/connect`](https://www.npmjs.com/package/@omnizapi/connect)). With it, you can [connect channels](/en/channels/connect-channel) directly within your system, without needing to access the dashboard.

<Note>
  The Public Key can be exposed in your application's frontend, as it has limited permissions for channel connection only.
</Note>

Two API routes accept the Public Key: [SDK origins](/en/channels/sdk-info) and [List Messenger pages](/en/channels/list-messenger-pages). On the others, use the Secret Key.

Example usage:

```javascript
import OmniZapi from '@omnizapi/connect';

const client = OmniZapi.newClient({
  publicKey: 'YOUR_PUBLIC_KEY'
});
```

---

## Secret Key

The Secret Key is used for authentication in all {projectName} APIs. It must be sent in the `Authorization` header as a Bearer token in every request.

<Warning>
  The Secret Key must **never** be exposed in the frontend. Use it only in your application's backend.
</Warning>

Example usage:

```bash
curl -X GET https://api.omni.z-api.io/whatsapp/businesses \
  -H "Authorization: Bearer YOUR_SECRET_KEY"
```

## Common errors

These errors apply to the API routes, in any product area (channels, templates, messages, webhooks). The body is `{"error": "<text>"}`. When the error comes from an internal service in JSON, the `error` field carries that object.

| Status | `error` response | When |
|---|---|---|
| `400` | `Authorization invalid` | `Authorization` header missing, or key malformed or nonexistent |
| `400` | `<ip> not allowed` | The source IP is not on the workspace [IP list](/en/security/ip-restriction). When the source IP cannot be identified: `ip not allowed` |
| `400` | `Required request body is missing` | Body missing or unreadable on a route that requires a body |
| `404` | `Instance not found` (`instance not found` on the message routes) | The channel does not exist or belongs to another workspace |
| `422` | `instance is not provisioned` | Message routes: the channel has not finished being provisioned |
| `422` | `instance subscription is not active` | Message routes: the channel has no active subscription |
| `422` | `You are blocked, contact support.` | Message routes: the workspace is blocked |
| `422` | `operation not supported for this instance` | Message routes: the channel type does not accept the operation |
| `502` | `integration_unavailable` | Failure in an internal service. The response carries `message`. Try again in a few moments |
| `504` | `integration_timeout` | The service did not answer in time. On a read, repeating is safe |
| `504` | `outcome_unknown` | The deadline passed on an operation that changes data. Check the state before repeating |
| `504` | `template_sync_timeout` | The template synchronization with Meta passed the deadline and is still running. List the templates again in a few moments |

The [message](/en/messages/introduction) routes and the [Z-API compatibility](/en/z-api/limitations) have their own errors, described in each section.

## Summary

| Key | Usage | Where to use | Can expose in frontend? |
|---|---|---|---|
| **Public Key** | [Channel connection SDK](/en/channels/connect-channel) | Frontend or backend | Yes |
| **Secret Key** | All API calls ([channels](/en/channels/introduction), [templates](/en/templates/introduction), [messages](/en/messages/introduction)) | Backend only | No |
