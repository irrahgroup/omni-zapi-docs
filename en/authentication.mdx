## API Credentials

{projectName} uses a key pair: **Public Key** and **Secret Key**. Both are generated in the **Security** menu of the dashboard: [Security](https://app.omni.z-api.io/app/security).

---

## Public Key

The Public Key is used by the channel connection SDK ([`@omnizapi/connect`](https://www.npmjs.com/package/@omnizapi/connect)). With it, you can [connect channels](/en/channels/connect-channel) directly within your system, without needing to access the dashboard.

<Note>
  The Public Key can be exposed in your application's frontend, as it has limited permissions for channel connection only.
</Note>

Example usage:

```javascript
import OmniZapi from '@omnizapi/connect';

const client = OmniZapi.newClient({
  publicKey: 'YOUR_PUBLIC_KEY'
});
```

---

## Secret Key

The Secret Key is used for authentication in all {projectName} APIs. It must be sent in the `Authorization` header as a Bearer token in every request.

<Warning>
  The Secret Key must **never** be exposed in the frontend. Use it only in your application's backend.
</Warning>

Example usage:

```bash
curl -X GET https://api.omni.z-api.io/whatsapp/businesses \
  -H "Authorization: Bearer YOUR_SECRET_KEY"
```

## Authentication errors

This section applies to the **Omni API** (`https://api.omni.z-api.io/v1/...`). When the Secret Key is rejected, the Omni API responds `401` with the `WWW-Authenticate: Bearer` header and the body `{"error": "Authorization invalid", "message": <text>}`. The `message` explains the reason and what to do:

| Reason | `message` |
|---|---|
| Header missing or empty | `Authorization invalid: the Authorization header is missing or empty. Send the workspace Secret Key as "Authorization: Bearer <secret-key>". See https://developer.omni.z-api.io/en/authentication` |
| Public Key (starts with `pk_`) | `Authorization invalid: this is the Public Key, which only works in the channel connection SDK. Send the workspace Secret Key as "Authorization: Bearer <secret-key>". See https://developer.omni.z-api.io/en/authentication` |
| Wrong format (e.g. the channel token) | `Authorization invalid: the value sent is not a Secret Key. Send the workspace Secret Key, generated under Security in the panel, as "Authorization: Bearer <secret-key>". The channel token is not accepted here. See https://developer.omni.z-api.io/en/authentication` |
| Nonexistent or revoked | `Authorization invalid: this Secret Key does not exist or is no longer valid. Copy the current Secret Key under Security in the panel and send it as "Authorization: Bearer <secret-key>". See https://developer.omni.z-api.io/en/authentication` |

`<secret-key>` is literal: the response never echoes the value you sent. Handle the error by `error`; the `message` is for reading and may change.

<Note>
  The Secret Key only accepts the format `^[a-z0-9_]+$`. The channel token is **uppercase** hex, so if it is pasted in place of the Secret Key it falls under **wrong format**. An OAuth app JWT (three non-empty dot-separated segments) is validated by the OAuth path: if valid, it is accepted; if invalid or expired, the API responds `401` with `WWW-Authenticate: Bearer error="invalid_token"` and `{"error": "invalid_token"}`. On routes OAuth does not cover (the `/send-*` routes without a message type and `GET`/`DELETE` on `messages/{messageId}`), the same value follows the Secret Key path and gets the **wrong format** `401`.
</Note>

<Note>
  The `401` above is from the **Omni API**. On the [compatible Z-API route](/z-api/introduction) (`/instances/{id}/token/{token}/...`) authentication **has not changed**: the rejection comes as `{"error": "Authorization invalid"}`, without `message` and without `WWW-Authenticate` — `400` when the header is missing or empty and `422` when the format is invalid or the key does not exist. The accepted format is the same (`^[a-z0-9_]+$`), so the channel token pasted in place of the Secret Key is also refused there, with `422`.
</Note>

## Summary

| Key | Usage | Where to use | Can expose in frontend? |
|---|---|---|---|
| **Public Key** | [Channel connection SDK](/en/channels/connect-channel) | Frontend or backend | Yes |
| **Secret Key** | All API calls ([channels](/en/channels/introduction), [templates](/en/templates/introduction), [messages](/en/messages/introduction)) | Backend only | No |
