## One piece of code, five channels

You do **not** write one flow per channel. The SDK reads the channel type and dispatches the right flow by itself:

```javascript
import OmniZapi from '@omnizapi/connect';

const client = OmniZapi.newClient({ publicKey: 'YOUR_PUBLIC_KEY' });

// Identical for WhatsApp, Instagram, Messenger and Telegram; WhatsApp Web also needs getQRCode
const response = await client.connect({ channelId: 'CHANNEL_ID' });

if (response.success) {
  await fetch('/my-backend/connect-channel', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(response),
  });
}
```

<Note>
  WhatsApp Web also needs the `getQRCode` function, which fetches the QR Code from your backend. The other channels ignore it, so you can always pass it. See [WhatsApp Web](/en/connect/whatsapp-web).
</Note>

The type comes from the channel, not from the call. You set the type in [Create channel](/en/channels/create-channel) and the SDK works out the rest.

## What happens under the hood

<Steps>
  <Step title="The SDK queries the channel">
    It calls [`GET /instances/{channelId}/sdk-info`](/en/channels/sdk-info) to find out the channel type, the matching Meta app and the [allowed origins](/en/channels/sdk-info).
  </Step>
  <Step title="It dispatches the type's flow">
    Each type has its own authorization path — Meta OAuth, QR Code or bot token.
  </Step>
  <Step title="It returns the connection data">
    The returned object changes depending on the channel. See the table below.
  </Step>
  <Step title="You finish on the backend">
    Send the result to your backend and call the finishing route for the channel type, with the Secret Key. Each channel has its own route: see the Finish the connection on the backend section below.
  </Step>
</Steps>

## Authorization flow per channel

|  | Meta Cloud API | WhatsApp Web | Instagram | Messenger | Telegram |
|---|---|---|---|---|---|
| **How it authorizes** | Meta Embedded Signup | QR Code | Instagram OAuth | Facebook OAuth + page selection | Bot token |
| **Page** | [Meta WhatsApp](/en/connect/meta-whatsapp) | [WhatsApp Web](/en/connect/whatsapp-web) | [Instagram](/en/connect/instagram) | [Messenger](/en/connect/messenger) | [Telegram](/en/connect/telegram) |

## The response changes per channel

All of them return `success`, `channelId` and `type`, the channel type. The rest depends on the type:

| Field | Meta Cloud API | WhatsApp Web | Instagram | Messenger | Telegram |
|---|:---:|:---:|:---:|:---:|:---:|
| `code` | ✅ | ❌ | ✅ | ✅ | ❌ |
| `wabaId` | ✅ | ❌ | ❌ | ❌ | ❌ |
| `phoneId` | ✅ | ❌ | ❌ | ❌ | ❌ |
| `coexistence` | ✅ | ❌ | ❌ | ❌ | ❌ |
| `redirectUri` | ❌ | ❌ | ✅ | ✅ | ❌ |
| `accessToken` | ❌ | ❌ | ✅ | ✅ | ❌ |
| `pageId` | ❌ | ❌ | ❌ | ✅ | ❌ |
| `botToken` | ❌ | ❌ | ❌ | ❌ | ✅ |

## Finish the connection on the backend

Send the whole object to your backend. There, use the `type` field to pick the finishing route and build the body from the SDK result, always with the Secret Key:

|  | Meta Cloud API | WhatsApp Web | Instagram | Messenger | Telegram |
|---|---|---|---|---|---|
| **Finishing route** | [`POST /v1/channels/{channelId}/connect`](/en/channels/connect-channel) | No finishing step | [`POST /v1/channels/{channelId}/activate-instagram`](/en/channels/activate-instagram) | [`POST /v1/channels/{channelId}/activate-messenger`](/en/channels/activate-messenger) | [`POST /v1/channels/{channelId}/activate-telegram`](/en/channels/activate-telegram) |
| **Body, from the SDK result** | `code`, `wabaId`, `phoneId` and `coexistence` | The channel connects when the QR Code is scanned. Check it with [`GET /v1/channels/{channelId}/zapi/status`](/en/channels/zapi-status) | `{"code", "redirectUri"}` | `{"pageId", "accessToken", "redirectUri"}`. The page and the `accessToken` come from [List Messenger pages](/en/channels/list-messenger-pages); see [Messenger](/en/connect/messenger) | `{"token": "<botToken from the SDK>"}`. The field is named `token`, not `botToken` |

<Warning>
  `POST /v1/channels/{channelId}/connect` is only for the Official WhatsApp. With the result of another channel, it answers `400` with `{"error":"wabaId is required"}`.
</Warning>

<Warning>
  Connecting only works from allowed domains, and the SDK fails silently when the origin is not on the list. Read [SDK origins](/en/channels/sdk-info) before integrating.
</Warning>

## Without the SDK

The SDK exists because each channel has a different authorization flow on its source platform, and all of them need a browser window. If you need to build this by hand, each channel page describes the authorization URL, the scopes and the parameters used.
