## Event envelope

Every request sent to your webhook has the following top-level structure:

```json
{
  "message": { ... },
  "messageEventType": "NEW_MESSAGE"
}
```

| Field | Type | Description |
|---|---|---|
| `message` | object | Complete message object |
| `messageEventType` | string | Event type — currently `"NEW_MESSAGE"` for all message events |

## Common message fields

All payloads share the same fields in the `message` object, regardless of content type:

| Field | Type | Description |
|---|---|---|
| `_id` | string | Unique message ID |
| `tenant` | string | Workspace ID |
| `tenant_owner` | string | Workspace owner email |
| `channel_id` | string | ID of the channel that received/sent the message |
| `created_by` | string | Internal message origin |
| `created` | number | Creation timestamp (epoch ms) |
| `metadata.from_api` | boolean | `true` when sent via API |
| `metadata.from_me` | boolean | `true` when sent by the business; `false` when received from the contact |
| `metadata.middleware` | string | Channel platform (e.g. `"META_WHATSAPP"`) |
| `metadata.forwarded` | boolean | `true` if the message was forwarded |
| `sender.identifier` | string | Identifier of the sender |
| `sender.name` | string | Name of the sender |
| `recipient.identifier` | string | Recipient phone number (country code + area code + number) |
| `contents` | array | Text and interactive message contents |
| `attachments` | array | Media attachments (image, audio, video, sticker) |
| `webhook_processed` | boolean | Internal processing control flag |

## Group messages

<Note>
  In Z-API format webhooks, sent to [Z-API Compatibility](/en/z-api/introduction) channels, a message received from a group follows the Z-API structure: `phone` and `chatName` identify the group, `participantPhone` and `participantLid` identify the sender, and the status callback carries `isGroup: true`.
</Note>

## Content types

The field that differentiates the message type is the `@class` inside each item of `contents` or `attachments`, combined with the `type` field.

## Status callbacks

Message status events carry the type in `contents[0].type` (for example, `DeliveryCallback`, `MessageStatusCallback` or `ErrorCallback`) and the `_id` of the message they refer to. Use the `_id` to link the status to the message. When the message is found, two fields of the `message` object tell you which message the status belongs to:

| Field | Type | Description |
|---|---|---|
| `metadata.from_me` | boolean | Direction of the message the status refers to: `true` when the business sent it, `false` when it was received from the contact. It is the same value as in the message webhook |
| `recipient.identifier` | string | Recipient reported by the channel. For a message sent by the business, when the channel reports the contact through an internal identifier, the status carries the message's `recipient.identifier`: on WhatsApp, the contact's phone number (country code + area code + number) or the group ID. Otherwise, you get the identifier the channel reported |
| `metadata.from_api` | boolean | Comes from the channel and may be `false` even for a message sent through the API. Do not use this field to filter statuses |
| `contents[0].phone` | string | Contact identifier as the channel reported it in the status. It may not be the phone number |

Use `metadata.from_me` to know where the message came from and `recipient.identifier` for the recipient. If the message is not found, the status arrives with the values the channel reported.

`RECEIVED` status example (message delivered to the contact), with the internal identifier in `contents[0].phone` and the phone number in `recipient.identifier`:

```json
{
  "message": {
    "_id": "019E6F1B0C2A7D4E8F1A2B3C4D5E6F70",
    "channel_id": "019E4C54B1B375A28970B605CA9B03C3",
    "metadata": {
      "@class": ".Metadata",
      "forwarded": false,
      "from_api": false,
      "from_me": true
    },
    "recipient": {
      "@class": ".Recipient",
      "identifier": "5511999990000",
      "name": ""
    },
    "contents": [
      {
        "@class": ".StateItem",
        "type": "MessageStatusCallback",
        "phone": "100000000000001@lid",
        "moment": 1779980476000,
        "state": { "@class": ".Received", "name": "RECEIVED" }
      }
    ]
  }
}
```

<Note>
  **Change announced on 11/04/2026, effective from the following version rollout.** Until then, on some channels, the status of a message sent by the business may arrive with `metadata.from_me: false` and, in `recipient.identifier`, an internal channel identifier instead of the phone number. After the rollout, the status carries `from_me: true` and the message's recipient. On Instagram and Messenger channels, statuses of messages sent by the business also start carrying `from_me: true`. Z-API format webhooks, from [Z-API Compatibility](/en/z-api/introduction), do not change.
