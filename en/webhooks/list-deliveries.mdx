## Overview

Returns the deliveries of the webhooks in the secret key's workspace, newest first, by event time. Each item has the status and a summary of the last attempt. The list has no body, URL, secret or credential: to see the attempts, use [Get delivery](/en/webhooks/get-delivery).

See the possible statuses in [Delivery center](/en/webhooks/deliveries#delivery-status).

### Period

- Without `from`, the list starts 24 hours before the call. Without `to`, it goes up to the time of the call.
- `from` must be earlier than `to`.
- If `from` is earlier than the period your plan keeps, the list starts at the beginning of that period and responds `fromAdjusted: true`.

If the response is `503`, the history took more than 5 seconds. Ask for a shorter period.

### Filters

| Parameter | What it filters |
|---|---|
| `webhookId` | One webhook |
| `status` | One status: `SUCCEEDED`, `RETRYING`, `FAILED`, `NOT_SENT`, `EXPIRED`, `UNKNOWN` or `RESENT` |
| `eventType` | One event type, such as `MESSAGE_RECEIVED` or `UPDATE_TEMPLATE_STATUS` |
| `eventId` | One event, by the UUID in `x-webhook-event-id` |
| `from`, `to` | The period, in ISO-8601 (for example, `2026-11-24T00:00:00Z`) |
| `destination` | One destination address, 1 to 2048 characters, not starting with `#` |
| `destinationUnavailable` | Only `true`: deliveries with no readable destination address. Cannot be combined with `destination` |

`status` and `eventType` accept upper or lower case. A delivery with a resend in progress only shows up in `status=RESENT`.

`destination` is the address with sensitive parts hidden, without query or fragment, with scheme and host in lower case, without the default port and without the trailing slash.

### Pagination

`limit` goes from 1 to 100, and the default is 50. The response has no total.

For the next page, repeat the call with the same filters and with `cursor` equal to the `nextCursor` you received. When `nextCursor` is `null`, there are no more pages. The cursor is opaque: do not build or change it.

### Errors

An invalid filter responds `400`, with the reason in `error.message`. For example, `{"error": {"message": "from deve ser anterior a to"}}`.

### Deliveries to connected apps

Deliveries to a connected app have `source: "APP"` and the app name in `appName`. They cannot be resent.
