## What is the global webhook?

Unlike **channel** webhooks and the **default** webhook, the global webhook receives only **account events**: WhatsApp templates, billing, Meta account restriction and channel disconnection. It does **not** depend on an instance (`instanceId = null`).

They coexist with the per-channel webhook routes, which remain unchanged. Template event routing is handled by the internal service independently of any instance.

<Note>
  The concepts common to all three webhook types (who can manage webhooks, URL rules, authentication, HMAC signing, and payload formats) are in the [Introduction](/en/webhooks/introduction).
</Note>

## Authentication

All routes require the header:

```
Authorization: Bearer <secret-key>
```

## Accepted events

The global webhook accepts **only** account events: template events, the channel disconnection notice (`CHANNEL_DISCONNECTED`), billing events and the Meta account restriction (`ACCOUNT_RESTRICTION`). Sending a channel event results in `422`.

| Value (exact, SNAKE_CASE) | Meaning |
|---|---|
| `UPDATE_TEMPLATE_STATUS` | Template status update (approved/rejected etc.) |
| `UPDATE_TEMPLATE_CATEGORY` | Template category update |
| `CHANNEL_DISCONNECTED` | Channel disconnection notice, with a reason code. See [Channel disconnection notice](/en/webhooks/channel-disconnected) |
| `BILLING_PAYMENT_FAILED`, `BILLING_PAYMENT_RECOVERED`, `BILLING_SUBSCRIPTION_CANCELED`, `BILLING_INSTANCE_SUSPENDED`, `BILLING_INSTANCE_RELEASED` | Billing events. See [Billing and account restriction events](/en/webhooks/account-events) |
| `ACCOUNT_RESTRICTION` | Meta restriction of the WhatsApp Business account. See [Billing and account restriction events](/en/webhooks/account-events) |

## Business rules

1. **Event scope (required).**
   - **Global** webhook → only accepts account events (template, `CHANNEL_DISCONNECTED`, billing and `ACCOUNT_RESTRICTION`). A channel event → `422`.
   - **Channel** webhook → **cannot** subscribe to template events → `422`.
2. **Use `payloadFormat` `DEFAULT`.** The global webhook is delivered in `DEFAULT`; omit the field or send `DEFAULT`. With `ACCOUNT_RESTRICTION`, `Z_API` or `CHATWOOT` return `422` with `{"error": "ACCOUNT_RESTRICTION only supports DEFAULT payload format"}`. Platform events (billing and `CHANNEL_DISCONNECTED`) are delivered only in `DEFAULT`: a `PATCH` that would leave the webhook with these events in another format returns `422` with `{"error": "Platform events are delivered only in DEFAULT payload format"}`.
3. **`instanceId` stored as `null`** automatically — there is no instance field on these routes. `channelId` also comes back `null`.

## Important notes

<Note>
  **Per-tenant scope.** Read/update/delete operations are scoped by the `tenant` resolved from the `Authorization` header — there is no cross-tenant access by id.
</Note>

<Note>
  **Router cache.** After creating or updating the global webhook, routing may take up to ~5 min to reflect (cache TTL).
</Note>
