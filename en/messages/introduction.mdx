## What are free messages?

Free messages are messages you send **without needing an approved template**. You can send text, image, audio, video, document — any supported format — with complete freedom of content.

The only condition: the [conversation window](/en/conversation-window) of **24 hours** must be open.

## When can I use them?

The window opens when the **customer sends you a message**. From that moment, you have 24 hours to send free messages. Each new message from the customer resets the timer.

```
Customer sends message → Window opens (24h) → You send free messages
```

## What if the window is closed?

If the customer hasn't sent a message in the last 24 hours, the window is closed. In this case, the only option is to send a **Meta-approved template** through the [Send template](/en/messages/send-template) endpoint.

After the customer **replies** to the template, the window reopens and you can use free messages again.

```
Window closed → Send template → Customer replies → Window reopens (24h)
```

<Info>
  Need to send a template? See how at [Send template](/en/messages/send-template). To create and manage your templates, go to the [Templates](/en/templates/introduction) section.
</Info>

## Available types

All endpoints in this section use the same route:

`POST /v1/channels/{channelId}/messages`

What changes is the `content.type` field:

| Type | Description |
|---|---|
| `TEXT` | Simple text message |
| `IMAGE` | Image message |
| `AUDIO` | Audio message |
| `VIDEO` | Video message |
| `CONTACT` | Contact card |
| `STICKER` | Sticker |
| `LOCATION` | Location message |
| `INTERACTIVE_ACTION` | Message with action buttons (URL and call) |
| `INTERACTIVE_BUTTON` | Message with quick reply buttons |
| `INTERACTIVE_LIST` | List of options in sections — *in development* |
| `DOCUMENT` | File up to 100 MB, by URL or Base64 |
| `REACTION` | Emoji on a message in the conversation — *in development* |
| `LOCATION_REQUEST` | Asks for the customer's location — *in development* |
| `FLOW` | Opens a published flow — *in development* |
| `CATALOG` | Opens the account catalog — *in development* |
| `PRODUCT` | One catalog product — *in development* |
| `PRODUCT_LIST` | Showcase with sections — *in development* |
| `ORDER_DETAILS` | Invoice with payment — *in development* |
| `ORDER_STATUS` | Order progress — *in development* |
| `TEMPLATE` | Meta-approved template (outside the 24h window) |

## API response

When the send is accepted, the API responds with `200` and the message identifier:

```json
{
  "messageId": "01A0C92D0C957FE98B73C8BA0CACF741"
}
```

The `messageId` is a 32-character uppercase hexadecimal string. Store this value: you need it to react to the message or quote it later.

<Note>
  This is the same value your webhook receives as `message._id`. Use it to reconcile the send call with the event you receive — see the [payload structure](/en/webhooks/payloads).
</Note>

## Replying with a quote

On the Meta Cloud API channel, a message can go out as a reply to another message in the conversation. In the customer's WhatsApp, it shows the excerpt of the original message on top. Send the reference of the quoted message in `content.messageIdReply`:

```json
{
  "recipient": {
    "identifier": "5511999999999"
  },
  "content": {
    "type": "TEXT",
    "body": {
      "message": "Yes, we have it in size M."
    },
    "messageIdReply": "01A0C92D0C957FE98B73C8BA0CACF741"
  }
}
```

The reference can be:

- the `messageId` the API returned when sending;
- the webhook's `message._id`, of a received or sent message;
- the `identifier` of an item in the webhook's `contents` or `attachments`.

The quoted message must belong to the same channel and to the conversation with the same contact as the `recipient`. For Brazilian numbers, the contact with and without the ninth digit counts as the same.

The types that go out quoted are `TEXT`, `IMAGE`, `AUDIO`, `VIDEO`, `DOCUMENT`, `STICKER`, `LOCATION`, `INTERACTIVE_BUTTON`, `INTERACTIVE_ACTION` and `INTERACTIVE_LIST`. `TEMPLATE`, `REACTION` and `CONTACT` do not go out quoted.

The API finds the quoted message's Meta id on its own. Do not send `content.integrationIdReply`: together with `messageIdReply`, it is ignored; on its own, it makes the API refuse the send.

On the other channels, the reply does not go out quoted: the message reaches the customer as a regular message.

### When the API refuses the quote

The refusal happens before sending: the message is not sent, gets no `messageId` and generates no webhook.

| Status | `subCode` | When |
|---|---|---|
| `400` | — | `content.messageIdReply` empty or only spaces, or `content.integrationIdReply` without `content.messageIdReply`. The `code` is `VALIDATION_ERROR`, and the field comes in `message`: `"Field 'content.messageIdReply': ..."` |
| `422` | `REPLY_NOT_SUPPORTED` | The message type does not go out quoted |
| `422` | `QUOTED_MESSAGE_NOT_FOUND` | No message in this channel has that reference |
| `422` | `QUOTED_MESSAGE_OTHER_CHAT` | The quoted message belongs to a conversation with another contact |
| `422` | `QUOTED_MESSAGE_NOT_ACCEPTED` | Meta refused to send the quoted message, so there is no message to quote on WhatsApp |

In the `422` refusals, the `code` is `BUSINESS_RULE_VIOLATION`.

<Note>
  To quote a message you have just sent, wait for its `MESSAGE_DELIVERY` webhook. Before that, the quote may return `QUOTED_MESSAGE_NOT_FOUND`: in that case, repeat the call after the webhook.
</Note>

<Note>
  Meta delivers the reply without the quoted excerpt when the original message was deleted or is old, usually more than 30 days. The API does not refuse the quote because of the message's age.
</Note>

## Send errors

When the API refuses the send, the message is not sent. The response carries the HTTP status for the reason and the error code:

```json
{
  "timestamp": "2026-10-22T14:00:00.123Z",
  "code": "BUSINESS_RULE_VIOLATION",
  "subCode": "CHANNEL_DISCONNECTED",
  "message": "Channel is disconnected"
}
```

| Field | Description |
|---|---|
| `timestamp` | Date and time of the refusal, in UTC |
| `code` | Error category |
| `subCode` | Case code. Present only when the case has its own code |
| `message` | Error description. The text may change: handle the error by `code` and `subCode` |

### Disconnected channel

If the channel is not connected at the time of the call, the API responds `422` with `code` `BUSINESS_RULE_VIOLATION` and `subCode` `CHANNEL_DISCONNECTED`, the body in the example above. The message is not sent and is not kept to go out later.

To send again, reconnect the channel (see [Connect a channel](/en/connect/introduction)) and repeat the call.

### Other errors

| Status | `code` | When |
|---|---|---|
| `400` | `VALIDATION_ERROR` | The body does not fit the message type: a `content.type` that does not exist or a missing required field. The field comes in `message`, like `"Field 'content.type': invalid value"` |
| `422` | `BUSINESS_RULE_VIOLATION` | Another send rule refused the message. Without `subCode`, the reason is only in `message` |
| `502` | — | Failure on our side while processing the send. The body carries `"error": "integration_unavailable"`, or `code` with the fixed `message` `"Message sending failed"` |

<Note>
  Refusals made before the message moves on to sending, such as an invalid Secret Key or an inactive subscription, come in another format, with only the `error` field.
</Note>
