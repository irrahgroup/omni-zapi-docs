## Overview

Sends a message with a list of options grouped into sections. The customer taps the button, opens the list
and picks a row. The `content.type` field must be `INTERACTIVE_LIST`.

It is the format for when the options don't fit in buttons: a menu, a service catalog, time slots, branches.
Up to 3 options, prefer [quick reply buttons](/en/messages/send-interactive-button), which take one tap less.

## Fields

| Field | What goes in it |
|---|---|
| `body.message` | The message text. Required |
| `action.message` | The text of the button that opens the list. Required |
| `attachments` | The list sections, one per item. Required, with at least one section |
| `attachments[].title` | The section title. Required when there is more than one section |
| `attachments[].list` | The section rows, at least one |
| `attachments[].list[].id` | The row identifier, chosen by you. Required |
| `attachments[].list[].title` | The row text. Required |
| `attachments[].list[].description` | Supporting text below the row. Optional |
| `header.message` | The header, text only. Optional |
| `footer.message` | The footer. Optional |

The names are the ones on this page, not the Meta Cloud API ones: the button text goes in `action.message`,
and the rows go in `attachments[].list`. A body with `button` and `sections` is refused for missing
`action.message`.

## Meta Cloud API limits

On the Meta Cloud API channel, the API checks the Meta limits before accepting the send:

| Field | Limit |
|---|---|
| `body.message` | 1024 characters |
| `header.message` | 60 characters |
| `footer.message` | 60 characters |
| `action.message` | 20 characters |
| Rows | **10 in total, across all sections** |
| `attachments[].title` | 24 characters |
| `attachments[].list[].id` | 200 characters, not repeated within a section |
| `attachments[].list[].title` | 24 characters |
| `attachments[].list[].description` | 72 characters |

<Warning>
  The row limit is **in total**, not per section. Two sections with six rows each are refused: the maximum is
  ten rows, spread across as many sections as you want.
</Warning>

The same `id` may appear in different sections. Within one section, it may not.

## When the API refuses the list

If a required field is missing or a limit is exceeded, the API responds `400` with `code`
`VALIDATION_ERROR`, and the message is not sent. The `message` names the first field with a problem:

```json
{
  "timestamp": "2026-10-22T14:00:00.123Z",
  "code": "VALIDATION_ERROR",
  "message": "Field 'content.action.message': is required for message type INTERACTIVE_LIST"
}
```

The response carries only the first problem. Once that one is fixed, the next call may point to another.

| Case | `message` |
|---|---|
| No button text | `Field 'content.action.message': is required for message type INTERACTIVE_LIST` |
| Section with an empty `list` | `Field 'content.attachments[0].list': must have at least one row` |
| More than 10 rows | `Field 'content.attachments': must have at most 10 rows across all sections` |
| Body above the limit | `Field 'content.body.message': must be at most 1024 characters` |
| `id` repeated within the section | `Field 'content.attachments[0].list[1].id': must be unique within the section` |

## On WhatsApp Web

The required fields are the same, and the limits in the table above are not checked. The rows of all
sections show up in a single list, without the section title, and the footer is not sent.

## The customer's reply

On the Meta Cloud API channel, the customer's choice reaches your [webhook](/en/webhooks/payloads) as a
received message. The content is in `contents[0]`:

| Field | What it carries |
|---|---|
| `type` | `BUTTON` |
| `title` | The `title` of the chosen row |
| `description` | The `description` of the chosen row |
| `external_information.list_reply_id` | The `id` you sent in the row |

Identify the option by the `id`, without relying on the displayed text, which can change without breaking
the integration.

<Note>
  Details of the Meta Cloud API rule in [conversation window](/en/conversation-window). See [what each channel accepts](/en/channels/message-support) for every channel.
</Note>

<Note>
  If the channel is disconnected, the API refuses the send with `422` and `subCode` `CHANNEL_DISCONNECTED`, and the message is not sent. See [Send errors](/en/messages/introduction#send-errors).
</Note>
