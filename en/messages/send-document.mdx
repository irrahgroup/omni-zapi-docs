## Overview

Sends a file to the contact. The `content.type` field is `DOCUMENT`.

The name the customer sees is built from `name` and `extension`: `"name": "invoice"` with `"extension": "pdf"`
arrives as `invoice.pdf`, with the PDF icon.

## Request body

By URL:

```json
{
  "recipient": { "identifier": "5511999999999" },
  "content": {
    "type": "DOCUMENT",
    "attachments": [
      {
        "url": "https://yourstore.com/invoice.pdf",
        "name": "invoice",
        "extension": "pdf",
        "caption": "Here is your invoice"
      }
    ]
  }
}
```

By Base64, with the file type prefix in the `url` itself:

```json
{
  "recipient": { "identifier": "5511999999999" },
  "content": {
    "type": "DOCUMENT",
    "attachments": [
      {
        "url": "data:application/pdf;base64,JVBERi0xLjQK...",
        "name": "invoice",
        "extension": "pdf",
        "caption": "Here is your invoice"
      }
    ]
  }
}
```

## Attachment fields

| Field | Description |
|---|---|
| `url` | The `https` address of the file, or the Base64 content with the type prefix, like `data:application/pdf;base64,` |
| `name` | File name, **without** the extension |
| `extension` | Extension, without the dot: `pdf`, `xlsx`, `docx`. It is what defines the icon. Without it, the file arrives with no name |
| `caption` | Caption, shown with the file |

<Warning>
  This API does not read the `fileName` field. It is ignored without an error, and the file arrives with no name.
  Send the name in `name` and the extension in `extension`.
</Warning>

## Rules

| Rule | Value |
|---|---|
| Size | up to 100 MB |
| Types | PDF, Word, Excel, PowerPoint, text |
| Caption | up to 1024 characters |

## What changes on each channel

| Channel | How the file goes |
|---|---|
| Meta Cloud API and WhatsApp Web | By URL or Base64. Name and caption arrive as you sent them |
| Telegram | **URL only.** For PDF, ZIP and GIF, the name shown is the one at the end of the URL |
| Instagram | **PDF only, URL only**, with no name and no caption |

The conditions are explained in [what each channel accepts](/en/channels/message-support#document-on-instagram-and-telegram).

## When the channel refuses the file

The API answers `200` with the `messageId` as soon as it accepts the request. If the channel later refuses the
file, for example a Base64 on Telegram or a spreadsheet on Instagram, the message does not arrive, and the
failure comes in the message status webhook (`MESSAGE_STATUS`). See [channel webhooks](/en/webhooks/channel-webhooks).

<Note>
  On the [Z-API Compatibility](/en/z-api/messages/send-document) the send uses another format, with `fileName`.
  There is a known defect in that field there today: with the extension the file arrives as `invoice.pdf.pdf`,
  and without it it arrives as `invoice.null`.
</Note>
