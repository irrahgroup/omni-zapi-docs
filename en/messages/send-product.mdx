## Overview

Sends a single catalog product. The photo, the name and the price come from Commerce Manager.

The `content.type` field must be `INTERACTIVE_SINGLE_PRODUCT`.

## Request body

```json
{
  "recipient": {
    "identifier": "5511999999999"
  },
  "content": {
    "type": "INTERACTIVE_SINGLE_PRODUCT",
    "body": {
      "message": "Este é o produto que você perguntou."
    },
    "footer": {
      "message": "Estoque limitado"
    },
    "action": {
      "catalogId": "1234567890",
      "productRetailerId": "SKU-1042"
    }
  }
}
```

## Fields

| Field | Required | Description |
|---|:---:|---|
| `content.body` | yes | Message body. It may be empty (`{}`) |
| `content.body.message` | no | Message text |
| `content.footer.message` | no | Footer |
| `content.action.catalogId` | no | Catalog id in Commerce Manager. Meta requires it |
| `content.action.productRetailerId` | no | Product SKU (`retailer_id`). Meta requires it |

## Rules

| Rule | Value |
|---|---|
| `catalogId` and `productRetailerId` | the API does not check them before sending: without them, or with a SKU that does not exist, Meta refuses after the `200` and the message does not arrive |

<Note>
  Without `content.body`, the API responds `400` with `code` `VALIDATION_ERROR` and `message` `"Field 'content.body': is required for message type INTERACTIVE_SINGLE_PRODUCT"`, and the message is not sent.
</Note>

<Note>
  On the other channels, the API does not refuse this type before sending: it responds `200`, but the message does not reach the customer.
</Note>

<Note>
  Details of the Meta Cloud API rule in [conversation window](/en/conversation-window). See [what each channel accepts](/en/channels/message-support) for every channel.
</Note>

<Note>
  If the channel is disconnected, the API refuses the send with `422` and `subCode` `CHANNEL_DISCONNECTED`, and the message is not sent. See [Send errors](/en/messages/introduction#send-errors).
</Note>

<Note>
  When the send is accepted, the API responds `200` with the `messageId`. See [API response](/en/messages/introduction#api-response).
</Note>

<Note>
  This type has no `send-*` route of its own: `send-product` responds `422` `send_route_not_supported`. Send it with `POST /v1/channels/{channelId}/messages`.
</Note>
