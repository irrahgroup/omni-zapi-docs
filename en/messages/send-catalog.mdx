## Overview

Sends a message that opens the catalog connected to your account in Commerce Manager.

The `content.type` field must be `INTERACTIVE_CATALOG`.

## Request body

```json
{
  "recipient": {
    "identifier": "5511999999999"
  },
  "content": {
    "type": "INTERACTIVE_CATALOG",
    "body": {
      "message": "Chegaram novidades na loja. Toque para ver o catálogo completo."
    },
    "footer": {
      "message": "Preços válidos enquanto durar o estoque"
    },
    "action": {
      "id": "SKU-1042"
    }
  }
}
```

## Fields

| Field | Required | Description |
|---|:---:|---|
| `content.body` | yes | Message body |
| `content.body.message` | no | Message text. Meta requires the text and accepts up to 1024 characters |
| `content.footer.message` | no | Footer. Meta accepts up to 60 characters |
| `content.action.id` | no | SKU (`retailer_id`) of the product shown on the cover. Without it, Meta uses the first item of the catalog |

## Rules

| Rule | Value |
|---|---|
| Catalog | must be connected to the account in Commerce Manager |
| Meta limits | the API does not check the sizes before sending; the Meta refusal arrives after the `200` |

<Note>
  Without `content.body`, the API responds `400` with `code` `VALIDATION_ERROR` and `message` `"Field 'content.body': is required for message type INTERACTIVE_CATALOG"`, and the message is not sent.
</Note>

<Note>
  On the other channels, the API does not refuse this type before sending: it responds `200`, but the message does not reach the customer.
</Note>

<Note>
  Details of the Meta Cloud API rule in [conversation window](/en/conversation-window). See [what each channel accepts](/en/channels/message-support) for every channel.
</Note>

<Note>
  If the channel is disconnected, the API refuses the send with `422` and `subCode` `CHANNEL_DISCONNECTED`, and the message is not sent. See [Send errors](/en/messages/introduction#send-errors).
</Note>

<Note>
  When the send is accepted, the API responds `200` with the `messageId`. See [API response](/en/messages/introduction#api-response).
</Note>

<Note>
  This type has no `send-*` route of its own: `send-catalog` responds `422` `send_route_not_supported`. Send it with `POST /v1/channels/{channelId}/messages`.
</Note>
