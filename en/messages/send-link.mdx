## Overview

Sends a text with a link preview: title, description and image. The data goes in the `content.body` object.

The `content.type` field must be `LINK`.

<ChannelNotes scope="SEND_LINK" lang="en" />

## Request body

```json
{
  "recipient": {
    "identifier": "5511999999999"
  },
  "content": {
    "type": "LINK",
    "body": {
      "message": "Veja a nossa nova coleção: https://exemplo.com/colecao",
      "url": "https://exemplo.com/colecao",
      "title": "Coleção de verão",
      "description": "Peças novas toda semana",
      "thumbnail": "https://exemplo.com/capa.jpg"
    }
  }
}
```

## Fields

| Field | Required | Description |
|---|:---:|---|
| `content.body` | yes | Message data |
| `content.body.message` | no | Message text |
| `content.body.url` | no | Link URL |
| `content.body.title` | no | Preview title |
| `content.body.description` | no | Preview description |
| `content.body.thumbnail` | no | Preview image URL |
| `content.body.linkType` | no | Preview format. The API passes the value on to the channel without checking it |

<Note>
  Without `content.body`, the API responds `400` with `code` `VALIDATION_ERROR` and `message` `"Field 'content.body': is required for message type LINK"`, and the message is not sent.
</Note>

<Note>
  The API does not refuse this type per channel before sending. The `200` confirms that the API accepted the message, not that the channel delivered it: follow the status through the [webhook](/en/webhooks/payloads). See [what each channel accepts](/en/channels/message-support).
</Note>

<Note>
  If the channel is disconnected, the API refuses the send with `422` and `subCode` `CHANNEL_DISCONNECTED`, and the message is not sent. See [Send errors](/en/messages/introduction#send-errors).
</Note>

<Note>
  When the send is accepted, the API responds `200` with the `messageId`. See [API response](/en/messages/introduction#api-response).
</Note>

<Note>
  The `POST /v1/channels/{channelId}/send-link` route takes the same body as this page and gives the same response. On it, `content.type` is optional and, if you send it, it must be `LINK`. With any other value, the API responds `400` `{"error": "invalid_request", "field": "content.type", "message": "content.type must be LINK on /send-link; leave it out, or send other types with POST /v1/channels/{id}/messages"}`, and the message is not sent. See [Routes by type](/en/messages/introduction#routes-by-type).
</Note>
