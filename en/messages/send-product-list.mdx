## Overview

Sends a showcase with catalog products, grouped into sections. Each item of `content.attachments` is a section, and each item of its `list` is a product.

The `content.type` field must be `INTERACTIVE_MULTI_PRODUCT`.

## Request body

```json
{
  "recipient": {
    "identifier": "5511999999999"
  },
  "content": {
    "type": "INTERACTIVE_MULTI_PRODUCT",
    "header": {
      "message": "Seleção da semana"
    },
    "body": {
      "message": "Separamos alguns produtos para você."
    },
    "footer": {
      "message": "Entrega em todo o Brasil"
    },
    "action": {
      "catalogId": "1234567890"
    },
    "attachments": [
      {
        "title": "Camisetas",
        "list": [
          {
            "id": "SKU-1042"
          },
          {
            "id": "SKU-1043"
          }
        ]
      },
      {
        "title": "Bermudas",
        "list": [
          {
            "id": "SKU-2001"
          }
        ]
      }
    ]
  }
}
```

## Fields

| Field | Required | Description |
|---|:---:|---|
| `content.header.message` | no | Header, text only. Meta requires it |
| `content.body` | yes | Message body |
| `content.body.message` | no | Message text |
| `content.footer.message` | no | Footer |
| `content.action.catalogId` | no | Catalog id in Commerce Manager. Meta requires it |
| `content.attachments` | no | The showcase sections |
| `content.attachments[].title` | no | Section title |
| `content.attachments[].list` | no | Products of the section. Always send it, even with a single product |
| `content.attachments[].list[].id` | no | Product SKU (`retailer_id`) |

## Rules

| Rule | Value |
|---|---|
| Products | Meta accepts up to **30**, adding up all sections |
| Valid products | at least one SKU must exist in the catalog |
| Checks | the API does not check sections, products or limits before sending; the Meta refusal arrives after the `200` |

<Note>
  Without `content.body`, the API responds `400` with `code` `VALIDATION_ERROR` and `message` `"Field 'content.body': is required for message type INTERACTIVE_MULTI_PRODUCT"`, and the message is not sent.
</Note>

<Note>
  On the other channels, the API does not refuse this type before sending: it responds `200`, but the message does not reach the customer.
</Note>

<Note>
  Details of the Meta Cloud API rule in [conversation window](/en/conversation-window). See [what each channel accepts](/en/channels/message-support) for every channel.
</Note>

<Note>
  If the channel is disconnected, the API refuses the send with `422` and `subCode` `CHANNEL_DISCONNECTED`, and the message is not sent. See [Send errors](/en/messages/introduction#send-errors).
</Note>

<Note>
  When the send is accepted, the API responds `200` with the `messageId`. See [API response](/en/messages/introduction#api-response).
</Note>

<Note>
  This type has no `send-*` route of its own. Send it with `POST /v1/channels/{channelId}/messages`.
</Note>
