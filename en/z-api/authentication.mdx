## Credentials

Each call carries two credentials: the channel `id` and `token`, in the path, and the workspace **Secret Key**, in the `Authorization` header. The Z-API `Client-Token` header is not used.

| Where | Credential | Example |
|---|---|---|
| Path | Channel `id` | `/channels/{id}/token/{token}/send-text` |
| Path | Channel `token` | `/channels/{id}/token/{token}/send-text` |
| Header | Secret Key | `Authorization: Bearer YOUR_SECRET_KEY` or `Authorization: YOUR_SECRET_KEY` |

The `Bearer` prefix is optional. The Secret Key is generated in the **Security** menu of the dashboard ([Security](https://app.omni.z-api.io/app/security)) and has only lowercase letters, digits and `_`. A value with other characters is refused.

```bash
curl -X POST https://zapi.omni.z-api.io/channels/YOUR_CHANNEL/token/YOUR_TOKEN/send-text \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_SECRET_KEY" \
  -d '{"phone": "5511999999999", "message": "Hello!"}'
```

<Warning>
  The Secret Key must **never** go to the frontend. Use it only in your application backend.
</Warning>

The Secret Key must belong to the same workspace as the channel. The Public Key is not valid on these routes.

## Order of checks and responses

The API checks, in this order, and stops at the first one that fails:

| Check | Response when it fails |
|---|---|
| Channel with the `id` and `token` of the path | `404` with `{"error": "instance not found"}` |
| `Authorization` header present | `400` with `{"error": "Authorization invalid"}` |
| Secret Key with a valid format and from the channel's workspace | `422` with `{"error": "Authorization invalid"}` |
| Workspace not blocked | `422` with `{"error": "You are blocked, contact support."}` |
| Source IP on the [IP list](/en/security/ip-restriction), when the workspace has one | `400` with `{"error": "203.0.113.10 not allowed"}`, with the refused IP in place of the example |

A wrong `id` or a wrong `token` answers the same `instance not found`, without saying which one failed. If the API cannot validate the Secret Key, the response is `502` with `{"error": "failed to validate authorization"}`.

An invalid `latitude` or `longitude` is refused with `400` before these checks, and on `send-location` a missing coordinate is too. See [Send location](/en/z-api/messages/send-location).

## Public Key and Secret Key

Z-API Omni works with a pair of keys, generated in [Security](https://app.omni.z-api.io/app/security):

| Key | Use | Can it be exposed in the frontend? |
|---|---|---|
| **Public Key** | Channel connection SDK | Yes |
| **Secret Key** | API calls, including these routes (`Authorization` header) | No, backend only |

Install the connection SDK from npm: [`@omnizapi/connect`](https://www.npmjs.com/package/@omnizapi/connect).
