## Overview

Method for marking as read a message the channel received from the contact. It works on **Official WhatsApp** channels (Meta official API).

## Attributes

| Attribute | Use |
|---|---|
| `messageId` | Required. The `messageId` that came in the received message webhook. |
| `phone` | Required, as in Z-API, but not used: the message is found by the `messageId`. |

The success response is `200`:

```json
{ "value": true }
```

## Differences from Z-API

- The `messageId` is the message id in {projectName}, the same one that comes in the webhook. In the default webhook format, it is `message._id`. It is not the message id in WhatsApp.
- The official API also marks as read the earlier messages of the conversation.
- A message sent by the channel itself answers `200`, with no effect.

## Errors

| Status | `error` | When |
|---|---|---|
| `400` | `phone is required` / `messageId is required` | `phone` or `messageId` missing or empty |
| `404` | `message not found` | The message does not exist or belongs to another channel |
| `422` | `message cannot be marked as read: it has no id at the channel provider` | The message has no WhatsApp id |
| `422` | `channel is disconnected` | The channel is disconnected |
| `422` | `the contact is outside the 24-hour window or is not a valid WhatsApp user` | The contact is outside the 24-hour window or is not a valid WhatsApp user |
| `422` | `the channel provider refused the request` | Meta refused the read |
| `422` | `instance subscription is not active` | The channel subscription is not active |
| `422` | `message action route is not available ...` | The channel is not Official WhatsApp. The text carries the channel type |
| `502` | `failed to mark message as read` | Failed to mark as read at Meta |

The API does not repeat the call after a `502`. You can call again.
