## How refusals respond

The compatibility serves WhatsApp Official channels (`META_WHATSAPP`) only. What it does not send or does not have always answers in JSON, after [authentication](/en/z-api/authentication), and nothing is sent:

| Case | Status | Body |
|---|---|---|
| Refused send route | `422` | `{"error": "<reason>"}`, in the [Refused sends](#refused-sends) table |
| Z-API route without an equivalent | `422` | `{"error": "<family> route is not available for META_WHATSAPP channels; available only on Z-API (WhatsApp Web) instances"}` |
| Wrong method for a route that exists | `405`, with the `Allow` header | `{"error": "method not allowed: use POST"}`, with the accepted methods in place of `POST` |
| Route that does not exist in the compatibility | `404` | `{"error": "route not found: this route does not exist in the Z-API compatibility"}` |
| Channel of another type, on a send route | `422` | `{"error": "instance middleware is not META_WHATSAPP"}` |
| Channel without an active subscription, on a send route | `422` | `{"error": "instance subscription is not active"}` |

When the channel is not WhatsApp Official, the channel type name replaces `META_WHATSAPP` in the refusal message of the routes without an equivalent.

## Refused sends

These routes exist in the compatibility, but they **do not send**. The response is `422`, with no `zaapId` or `messageId`.

| Route | `error` response |
|---|---|
| `send-button-pix` | `pix button is not supported for this channel` |
| `send-poll` | `poll is not supported for this channel` |
| `send-order` | `order is not supported for this channel` |
| `send-link-list` | `link list is not supported for this channel` |
| `send-carousel` | `carousel is not available for this channel yet` |
| `send-catalog` | `catalog message is not available for this channel yet` |
| `send-product` | `product message is not available for this channel yet` |
| `send-option-multi-list` | `multi-section option list is not available for this channel yet` |
| `send-option-list` | `option list is not available for this channel yet`. The payload is checked first: an error in it (for example `optionList.options is required`) comes in place of this message |
| `send-text-status`, `send-image-status`, `send-video-status` | `status (stories) route is not available for META_WHATSAPP channels; available only on Z-API (WhatsApp Web) instances` |
| Any send route with `editMessageId` or `editDocumentMessageId` | `message editing is not supported for this channel` |

The messages with "is not supported" are for features WhatsApp Official does not have. The ones with "is not available ... yet" are for features that are not available through this route yet.

### Routes with no converted content

These routes exist, but a body in the Z-API format is not converted into a message. The response is `422` with `{"error": "message has no content this route can send"}`, and nothing is sent:

- `send-poll-vote`
- `send-call`
- `send-chat-expiration` (the `chatExpiration` value is checked first: `24_HOURS`, `7_DAYS`, `90_DAYS` or `OFF`)
- `send-event`, `send-edit-event` and `send-event-response`
- `send-comment`
- `send-request-payment`
- `order-status-update` and `order-payment-update`
- `send-newsletter-admin-invite`

The same response applies to any send whose content would be an empty text, for example `send-messages` with a `message` of only spaces or `send-button-otp` without `code` and `message`.

## Field refusals on routes that send

| Route | When | `error` response |
|---|---|---|
| `send-button-actions` | `CALL` button | `call button is not supported for this channel` |
| `send-button-actions` | `URL` button with the copy-code link (`whatsapp.com/otp/code`) | `copy button is not supported for this channel` |
| `send-button-actions` | `URL` and `REPLY` buttons together | `URL and REPLY buttons cannot be sent together on this channel` |
| `send-button-actions` | More than one `URL` button | `only one URL button is supported for this channel` |
| `send-button-actions` | `URL` button with `image` | `image header with a URL button is not available for this channel yet` |
| `send-button-actions` | `REPLY` buttons with `title` or `footer` | `title and footer with REPLY buttons are not available for this channel yet` |
| `send-button-list` | `headerImage` and `headerVideo` together | `buttonList accepts headerImage or headerVideo, not both` |

The size and count limits are in [Send action buttons](/en/z-api/messages/send-button-actions) and [Send button list](/en/z-api/messages/send-button-list).

## Routes that send with a difference

| Feature | What happens |
|---|---|
| Reply with a quote (`messageId` on sends) | The field is accepted, but the message arrives without quoting the original |
| Private reply in a group (`privateAnswer`) | The field is not read |
| `send-gif` | Sent as an image |
| `send-ptv` | Sent as a regular video, not as a round video |
| `delayMessage` and `delayTyping` | Values above 15 are reduced to 15 |
| `mentioned` | Group conversations only. Outside one: `400` with `mentions are only allowed in groups` |

## Z-API routes without an equivalent

There are 149 Z-API routes. All of them answer `422` with `<family> route is not available for META_WHATSAPP channels; available only on Z-API (WhatsApp Web) instances`, after authentication. Each table shows the family name that goes in the message.

The methods a table has for a route are the only ones that answer `422`. Another method answers `405`.

The Z-API webhook, integrator and on-demand routes have no equivalent in the compatibility and answer `404`, like any route that does not exist.

<Info>
  For WhatsApp Web channels, Z-API Omni has its own routes, outside the compatibility: [QR Code](/en/channels/zapi-qr-code), [status](/en/channels/zapi-status), [disconnect](/en/channels/zapi-disconnect) and [device](/en/channels/zapi-device).
</Info>

## Instance routes the compatibility serves

`GET /status`, `GET /me`, `GET /device` and the queue (`queue`) answer in the Z-API format. See [Instance status](/en/z-api/instance/status), [Instance data](/en/z-api/instance/me), [Device](/en/z-api/instance/device) and [Queue](/en/z-api/instance/queue-count).
