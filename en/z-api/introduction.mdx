## What is the Z-API Compatibility version?

The **Z-API Compatibility** version was created to make it easy for customers currently using Z-API to migrate to {projectName} as their official API solution for WhatsApp.

We know that switching API providers can be a complex process — especially when you already have integrations running in production. That's why we developed this compatibility layer that maintains the same structure you already know.

## What changes in practice?

<Note>
  The only changes required in your application are the **base URL** and the **authentication header**. Additionally, not every Z-API route is available on every channel. See the [Channel compatibility](/en/z-api/limitations) page for what each channel does.
</Note>

<Warning>
  The Z-API Compatibility version serves **WhatsApp Official** (Meta's official API) and **WhatsApp Web** channels. A send to a channel of any other type, such as Instagram, Messenger or Telegram, is refused with `422`:

  ```json
  { "error": "instance middleware is not META_WHATSAPP" }
  ```

  The other Z-API routes also answer `422` on those channels. To use those channels, use the [{projectName} message routes](/en/messages/introduction).
</Warning>

| | Before (Z-API) | After (Omni Z-API) |
|---|---|---|
| **Base URL** | `https://api.z-api.io` | `https://zapi.omni.z-api.io` |
| **Authentication** | `Client-Token` header | `Authorization: Bearer {secret}` header |
| **Naming** | `instance` / `instance_id` | `channel` / `channel_id` |
| **URL Path** | `/instances/{id}/token/{token}` | `/instances/` or `/channels/` (both work) |
| **API Payloads** | — | Same structure |
| **Webhook Body** | — | Same structure |

### About naming

In {projectName}, what was previously called **instance** (`instance_id`) is now referred to as **channel** (`channel_id`). The concept is the same — it represents a connection to a WhatsApp number — but we adopted the term "channel" because it's more comprehensive, since {projectName} supports multiple messaging channels beyond WhatsApp.

<Note>
  For compatibility, the API accepts both `/instances/` and `/channels/` in the path. If you're migrating from Z-API, you can keep `/instances/` without any issues — your integrations will continue working. For new integrations, we recommend using `/channels/`.
</Note>

If today your application makes a call like:

```bash
curl -X POST https://api.z-api.io/instances/YOUR_INSTANCE/token/YOUR_TOKEN/send-text \
  -H "Content-Type: application/json" \
  -H "Client-Token: YOUR_CLIENT_TOKEN" \
  -d '{"phone": "5511999999999", "message": "Hello!"}'
```

Just change it to:

```bash
curl -X POST https://zapi.omni.z-api.io/channels/YOUR_CHANNEL/token/YOUR_TOKEN/send-text \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_SECRET" \
  -d '{"phone": "5511999999999", "message": "Hello!"}'
```

Note that **only the base URL and authentication header changed** — the path and body are identical.

The secret for the `Authorization` header is generated in the Omni Z-API dashboard when you create your channel. The request payloads and webhook bodies maintain exactly the same structure, ensuring your integrations continue working without breaking.

## Served channels

### WhatsApp Official

On a WhatsApp Official channel, the compatibility serves:

- **Sending messages**: text, media, contacts, location, links, buttons, reactions, catalog and carousel. Product, PIX button, option list, poll, order and link list answer `422`.
- **Mark message as read** (`read-message`).
- **[Groups](/en/z-api/groups/introduction)**: 12 of the 19 routes. It requires a verified Official Business Account (OBA), does not work on a coexistence number, the group has at most 8 participants and no one is added on creation (people join only through the invite link).
- **[Profile](/en/z-api/profile/introduction)**: business profile, about text and profile picture, with limits. Categories and business hours answer `422`, changing the profile name requires Meta review, and the picture accepts only an `http` or `https` URL and cannot be removed.
- **[Instance](/en/z-api/instance/introduction)**: status, instance data and device data.
- **[Queue](/en/z-api/queue/introduction)**: queries return empty, because messages are not queued, and the removal routes answer `422`.

Contacts, message actions (delete, forward, pin and reply to button or list), catalog management and chats are not served on this channel and answer `422`.

### WhatsApp Web

On a WhatsApp Web channel, the compatibility serves:

- **Sending messages**: the routes listed in the **Sending on a WhatsApp Web channel** section, below.
- **Message actions**: delete, forward, pin, reply to button, list or template button, and mark as read.
- **[Contacts](/en/z-api/contacts/introduction)**, **[groups](/en/z-api/groups/introduction)** (all 19 routes), **[catalog and products](/en/z-api/catalog/introduction)**, **[profile](/en/z-api/profile/introduction)**, **[queue](/en/z-api/queue/introduction)** and **[chats](/en/z-api/chats/introduction)**.

Instance status and data still answer `422` on this channel.

The `update-name` route renames the channel and works on any channel type. The full route-by-route table is in [Channel compatibility](/en/z-api/limitations).

## Sending on a WhatsApp Web channel

On a WhatsApp Web channel, these routes send with the same structure and the same response as WhatsApp Official:

- `send-text`, `send-image`, `send-video`, `send-audio`, `send-document/{extension}`, `send-sticker`, `send-contact`, `send-contacts`, `send-location`, `send-link`, `send-button-list`, `send-button-actions`, `send-button-otp`, `send-reaction`, `send-remove-reaction`

The other send routes, a send with `editMessageId` or `editDocumentMessageId`, and a body with `template`, `gif`, `gifUrl`, `ptv`, `carousel` or `carouselCards` answer `422` `instance middleware is not META_WHATSAPP`.

Differences from the Z-API itself:

- the response `messageId` is the message id in {projectName}, not the WhatsApp id;
- the `zaapId` is not in the instance queue: `DELETE /queue/{zaapId}` does not find this send;
- the `200` confirms that {projectName} accepted the send, not the delivery;
- quoted reply (`messageId`), mentions (`mentioned`), `delayMessage`, `viewOnce` and `stickerAuthor` do not reach the message, on either channel;
- a disconnected channel answers `502` `failed to send message`.

## Groups

Besides sending messages, Z-API Compatibility serves the 19 Z-API group routes. See the [Groups introduction](/en/z-api/groups/introduction) to learn what each route does on each channel type.

## How to migrate

<Steps>
  <Step title="Create your Omni Z-API account">
    Go to the [Dashboard](https://app.omni.z-api.io) and create your account.
  </Step>
  <Step title="Set up your channel">
    Create a new channel and connect your WhatsApp number.
  </Step>
  <Step title="Update the base URL and authentication">
    Replace `https://api.z-api.io` with `https://zapi.omni.z-api.io` and change the `Client-Token` header to `Authorization: Bearer YOUR_SECRET`.
  </Step>
  <Step title="Configure webhooks">
    Update the webhook callback URL in the Dashboard to point to your server. Incoming events will have the same structure as before.
  </Step>
  <Step title="Test and validate">
    Run send and receive tests to make sure everything is working correctly.
  </Step>
</Steps>
