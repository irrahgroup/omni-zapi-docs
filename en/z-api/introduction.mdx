## What is the Z-API Compatibility version?

The **Z-API Compatibility** version answers in the Z-API format. If you already integrate with Z-API, you migrate to Z-API Omni by changing the base URL and the authentication header, and you keep sending the same bodies and reading the same responses. The address is `https://zapi.omni.z-api.io`.

It serves **WhatsApp Official channels only** (`META_WHATSAPP`, Meta's official API). The Z-API routes that WhatsApp Official does not have, or that are not available yet, are refused with a clear response. The full list is in [Limitations and refusals](/en/z-api/limitations).

<Warning>
  A send to a channel of another type (WhatsApp Web, Instagram, Messenger or Telegram) is refused with `422`:

  ```json
  { "error": "instance middleware is not META_WHATSAPP" }
  ```

  A WhatsApp Official channel without an active subscription also gets `422`, with `{ "error": "instance subscription is not active" }`. To send through the other channels, use the [Z-API Omni message routes](/en/messages/introduction).
</Warning>

## What changes in practice

|  | Z-API | Z-API Omni |
|---|---|---|
| **Base URL** | `https://api.z-api.io` | `https://zapi.omni.z-api.io` |
| **Authentication** | `Client-Token` header | `Authorization` header with the Secret Key, with or without `Bearer` ([Authentication](/en/z-api/authentication)) |
| **Path** | `/instances/{id}/token/{token}/...` | `/instances/`, `/devices/` or `/channels/` (equivalent) |
| **Naming** | `instance_id` | `channel_id` |
| **Send body and response** | Z-API format | The same format on the routes that send ([Messages](/en/z-api/messages/introduction)) |
| **Webhooks** | Z-API format | Set `payloadFormat` to `Z_API` on the channel webhook or on the default webhook ([Webhooks](/en/webhooks/introduction)) |

### About naming

In Z-API Omni, what used to be called an **instance** (`instance_id`) is called a **channel** (`channel_id`). The concept is the same: the connection to a WhatsApp number. The term "channel" is broader because Z-API Omni has other messaging channels besides WhatsApp.

<Note>
  The API accepts `/instances/`, `/devices/` and `/channels/` in the path, with the same behavior. If you are migrating from Z-API, you can keep `/instances/`. In new integrations, use `/channels/`.
</Note>

If your application makes a call like this today:

```bash
curl -X POST https://api.z-api.io/instances/YOUR_INSTANCE/token/YOUR_TOKEN/send-text \
  -H "Content-Type: application/json" \
  -H "Client-Token: YOUR_CLIENT_TOKEN" \
  -d '{"phone": "5511999999999", "message": "Hello!"}'
```

Change the base URL and the authentication header:

```bash
curl -X POST https://zapi.omni.z-api.io/channels/YOUR_CHANNEL/token/YOUR_TOKEN/send-text \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_SECRET_KEY" \
  -d '{"phone": "5511999999999", "message": "Hello!"}'
```

`YOUR_CHANNEL` is the channel `id` and `YOUR_TOKEN` is its `token`, both returned when you [create the channel](/en/channels/create-channel) and when you [get it](/en/channels/get-channel). The Secret Key is generated in the **Security** menu of the dashboard.

## What the compatibility covers

| Group | What it answers |
|---|---|
| [Messages](/en/z-api/messages/introduction) | 42 `send-*` and order routes. Some send, some are refused with `422`. Each route is in the table of the messages introduction |
| [Instance](/en/z-api/instance/status) | `status`, `me`, `device` and the queue (`queue`), in the Z-API format |
| Z-API routes without an equivalent | 149 routes (groups, contacts, chats, catalog, communities, newsletters, business profile, privacy and tags, among others) refused with `422` |
| Other routes | A wrong method answers `405`; a route that does not exist answers `404` |

The response for each case is in [Limitations and refusals](/en/z-api/limitations).

## How to migrate

<Steps>
  <Step title="Create your Z-API Omni account">
    Go to the [Dashboard](https://app.omni.z-api.io) and create your account.
  </Step>
  <Step title="Create and connect a WhatsApp Official channel">
    Create a WhatsApp Official channel and connect the number. See [Connect WhatsApp Official](/en/connect/meta-whatsapp).
  </Step>
  <Step title="Update the base URL and authentication">
    Replace `https://api.z-api.io` with `https://zapi.omni.z-api.io` and the `Client-Token` header with `Authorization: Bearer YOUR_SECRET_KEY`.
  </Step>
  <Step title="Check the routes you use">
    Compare your integration's routes with [Messages](/en/z-api/messages/introduction) and [Limitations and refusals](/en/z-api/limitations). A refused route answers `422` with the reason, and nothing is sent.
  </Step>
  <Step title="Set up the webhooks">
    Point the channel webhooks to your server and use `payloadFormat` `Z_API` to keep the format. See [Webhooks](/en/webhooks/introduction).
  </Step>
  <Step title="Test and validate">
    Test sending and receiving before you move production traffic.
  </Step>
</Steps>
