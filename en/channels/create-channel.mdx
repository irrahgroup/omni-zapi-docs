## Overview

Creates a new channel. After creation, the channel needs to be connected (via dashboard or SDK) to start sending and receiving messages.

The channel starts in `TRIAL` for 2 days; to keep it, subscribe with [Subscribe channel](/en/channels/subscribe-channel).

The returned `id` is the `channelId` used in all API calls.

### Channel token

When the request is authenticated with the workspace **Secret Key**, the `201` response also includes the channel `token`:

```json
{
  "id": "019E4C54B1B375A28970B605CA9B03C3",
  "token": "F1B29C3D4E5A6B7C8D9E0F1A2B3C4D5E"
}
```

It is the same token that [Get channel](/en/channels/get-channel) returns with the Secret Key. The token identifies the channel on the routes in the Z-API format, with the token in the path. The routes in this reference use the Secret Key in the Authorization header.

Create channel accepts only the Secret Key.

Error responses do not change and carry no token.

<Note>
  The same applies to the equivalent routes `POST /v1/instances` and `POST /v1/devices`.
</Note>

### Available types

| Type | Platform |
|---|---|
| `META_WHATSAPP` | WhatsApp (Meta Official API) |
| `Z_API_WHATSAPP` | WhatsApp Web |
| `META_INSTAGRAM` | Instagram |
| `META_MESSENGER` | Messenger |
| `BOT_TELEGRAM` | Telegram |

### Unique name in the workspace

The channel name is unique among the active channels of the workspace. If another active channel already uses the same name, the creation is refused with `409`, and no channel is created:

```json
{
  "error": "channel_name_in_use",
  "message": "A channel with this name already exists in this workspace. Pick another one."
}
```

- The comparison ignores case and leading or trailing spaces: `Sales`, `sales` and ` Sales ` are the same name. The channel is stored without those spaces.
- Accents and inner spaces make names different: `Salés` and `Sa  les` are other names.
- The channel type does not matter: a `META_WHATSAPP` and a `BOT_TELEGRAM` channel cannot share a name in the workspace.
- A canceled channel that was not deleted still holds its name. A deleted channel frees the name.
- Recognize the refusal by the `error` field, which is stable. The `message` is always in English and can be shown to the user.

<Note>
  Channels created before this rule do not change, including the ones that share a name. If your integration creates channels with repeated names, handle the `409` by picking another name.
</Note>

### Errors

| Status | Body | When |
|---|---|---|
| `400` | `{"error":"Authorization invalid"}` | Secret Key missing, malformed or unknown |
| `400` | `{"error":"203.0.113.10 not allowed"}` | IP outside the [IP list](/en/security/ip-restriction) |
| `400` | `{"error":"type is required"}` | Body without `type` |
| `400` | `{"error":"Required request body is missing"}` | `type` outside the list of types, or invalid JSON |
| `409` | `{"error":"channel_name_in_use", ...}` | Name already used by another active channel |
| `422` | `{"error":"channel_type_not_enabled","message":"Z_API_WHATSAPP channel is not enabled for this workspace. Contact support."}` | WhatsApp Web not enabled for the workspace |
| `422` | `{"error":"Channel creation requires ENTERPRISE role"}` | Account without the ENTERPRISE role |
| `502` | `{"error":"integration_unavailable", ...}` | Integration failure; try again in a few moments |
| `504` | | The creation did not answer in time; before retrying, check in [List channels](/en/channels/list-channels) whether the channel was created |
