---
title: "Activate Instagram, Messenger or Telegram channel"
description: "Finish the connection of Instagram, Messenger and Telegram channels in your backend with the SDK data"
---

After the SDK's `client.connect()`, the connection of an Instagram, Messenger or Telegram channel ends in **your backend**, with an activation call. Each channel type has its own route:

| Channel type | Route | SDK connection |
|---|---|---|
| `META_INSTAGRAM` | [`POST /v1/channels/{channelId}/activate-instagram`](/en/channels/activate-instagram) | [Instagram](/en/connect/instagram) |
| `META_MESSENGER` | [`POST /v1/channels/{channelId}/activate-messenger`](/en/channels/activate-messenger) | [Messenger](/en/connect/messenger) |
| `BOT_TELEGRAM` | [`POST /v1/channels/{channelId}/activate-telegram`](/en/channels/activate-telegram) | [Telegram](/en/connect/telegram) |

<Warning>
  [`POST /v1/channels/{channelId}/connect`](/en/channels/connect-channel) only applies to `META_WHATSAPP`. Without `wabaId`, it refuses the call with `400` `{"error": "wabaId is required"}`. For Instagram, Messenger and Telegram, use the activation route of the channel type.
</Warning>

All three routes use the Secret Key in the `Authorization: Bearer YOUR_SECRET_KEY` header. Always call them from the backend. See [Authentication](/en/authentication).

## From the SDK to the body

`client.connect()` returns `code`, `redirectUri`, `pageId` or `botToken`, depending on the channel. Each activation route expects a different body:

| SDK field | Instagram | Messenger | Telegram |
|---|---|---|---|
| `code` | `code` | `code` | — |
| `redirectUri` | `redirectUri` | `redirectUri` | — |
| `pageId` | — | `pageId`, when the user administers more than one page | — |
| `botToken` | — | — | `token` |

<Note>
  `redirectUri` comes in the result of [`@omnizapi/connect`](https://www.npmjs.com/package/@omnizapi/connect) 1.1.1 or later.
</Note>

One way to build the call in the backend, from the channel type and the object the frontend received from the SDK:

```javascript
function activation(channelType, response) {
  switch (channelType) {
    case 'META_INSTAGRAM':
      return {
        path: 'activate-instagram',
        body: { code: response.code, redirectUri: response.redirectUri },
      };
    case 'META_MESSENGER':
      return {
        path: 'activate-messenger',
        // pageId: the one the SDK returned or the one the user picked from the page list
        body: { code: response.code, redirectUri: response.redirectUri, pageId: response.pageId },
      };
    case 'BOT_TELEGRAM':
      return {
        path: 'activate-telegram',
        body: { token: response.botToken },
      };
    default:
      throw new Error(`No activation for type: ${channelType}`);
  }
}

const { path, body } = activation(channelType, response);
const res = await fetch(
  `https://api.omni.z-api.io/v1/channels/${encodeURIComponent(channelId)}/${path}`,
  {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${process.env.OMNI_SECRET_KEY}`,
    },
    body: JSON.stringify(body),
  },
);
```

## Channel already active

Activating a channel that is already active at the provider responds `422`, with the provider error in the `error` field. The error name depends on the channel:

| Channel | Error |
|---|---|
| Instagram | `INSTAGRAM_META_IS_ALREADY_ACTIVATED` |
| Messenger | `MESSENGER_META_IS_ALREADY_ACTIVATED` |
| Telegram | `TELEGRAM_IS_ALREADY_ACTIVATED` |

There is one exception. If the channel is active at the provider, but disconnected on the platform and with an active subscription, the API deactivates and activates the channel again, once, without you having to do anything.

## Errors

| Status | Body | When it happens |
|---|---|---|
| `401` | `{"error": "Authorization invalid", "message": "..."}` | The Secret Key was refused. See the reasons in [Authentication](/en/authentication) |
| `403` | `{"error": "ip_not_allowed", "message": "..."}` | The source IP is off the list. See [IP restriction](/en/security/ip-restriction) |
| `404` | `{"error": "Instance not found"}` | The channel does not exist or belongs to another workspace |
| `422` | `{"error": { ... }}` or `{"error": "..."}` | The provider refused the activation, or the channel type does not match the route |
| `502` | `{"error": "integration_unavailable", "message": "..."}` | An internal service is unavailable. Try again in a few moments |
| `504` | `{"error": "integration_timeout", "message": "..."}` | The activation took too long. You can repeat the call |
| `504` | `{"error": "outcome_unknown", "message": "..."}` | The activation did not finish in time and may still be completed. Check the result before trying again |

In the provider `422`, the `error` field carries the provider envelope, in the same format as the [WhatsApp Web QR code refusal](/en/connect/whatsapp-web). The error name is in `error.errors[0].name`. When the provider refuses without that envelope, `error` comes as a generic text: `{"error": "The operation could not be completed right now. Try again in a few moments."}`.

<Note>
  The API does not validate the body before calling the provider. Usually, a missing field comes back as a provider `422`, not as `400`. On Telegram, an empty `token` (`""`) comes back as `422`, but without the `token` field the response can be `502` `integration_unavailable`. Always send the field.
</Note>

<Warning>
  The API only starts a new activation step within **50 seconds**, but a step that has already started runs to the end, and the gateway ends the request at **60 seconds**. Set your HTTP client timeout above 60 seconds, so you receive the API response.
</Warning>

## After the activation

With the channel active, use the `channelId` in the [free-form messages](/en/messages/introduction) endpoints. To turn the channel off, see [Disconnect channel](/en/channels/disconnect).
