The Z-API Omni promise is a single one: **one call, any channel**. The request body is the same for
WhatsApp, Instagram, Messenger and Telegram. Change the channel in the URL, and that is it.

What cannot be promised is that every platform accepts everything. Instagram has no location message.
Telegram has no call button. A product catalog only exists where there is a catalog. Most of those
limits belong to the platforms, and this page is the map of them, so you find out now instead of in the
middle of a test.

## The five channels, two lines each

<CardGroup cols={2}>
  <Card title="Meta Cloud API (Official)" icon="whatsapp">
    Meta's API, with a verified number and a business account. It is the channel that accepts the most:
    the only one with forms, catalog and templates. In exchange, it has the [24-hour
    window](/en/conversation-window).
  </Card>
  <Card title="WhatsApp Web" icon="qrcode">
    The QR code connection, with the phone paired. No window and no template: you write at any time,
    and you can edit the text you sent within the first 15 minutes.
  </Card>
  <Card title="Instagram and Messenger" icon="instagram">
    Direct message conversations. They accept text, media and buttons, and stop there: no contact card
    and no option list. Both have a 24-hour window.
  </Card>
  <Card title="Telegram" icon="telegram">
    A bot. It accepts almost everything and has no window, but it speaks another language: what is a
    message type on WhatsApp is sometimes a keyboard button there.
  </Card>
</CardGroup>

## How to read the table

| Mark | What it means | What to do |
|:---:|---|---|
| ✅ | It works. The body published on the endpoint page is valid as is. | Send it. |
| ⚠️ | It works **with a condition**, or it works in a similar way instead of the same way. | Read the caveat before promising it to your customer. |
| ❌ | It does not go out on this channel: the platform does not have the feature, or the API does not send this type yet. | See what to send instead, further down. |
| 🔍 | We could not find confirmation in the platform's documentation. | Treat it as "maybe" and test before relying on it. |

<Note>
  ⚠️ never means "it might work". It means that **it works and we know under which condition**, and
  the condition is spelled out below, and also on each endpoint page, right under its little table.
</Note>

### What happens when the channel does not accept it

In three cases the API refuses right away, with `422` `BUSINESS_RULE_VIOLATION`, and the message is not
sent: **location on Instagram**, **contact on Instagram** and **option list on Telegram**. On the other ❌,
the API accepts the call with `200`, the message is not sent, and the failure arrives through the
[status webhook](/en/webhooks/channel-webhooks). See [Send errors](/en/messages/introduction#send-errors).

Text and media are the common ground: they work on all five, with the same body. The exception is the
document, which has a condition on Instagram and Telegram. From there up, the channels start to disagree.
Polls are not available through the API yet, on any channel.

## When the customer answers with a tap

| Feature | Meta Cloud API | WhatsApp Web | Instagram | Messenger | Telegram |
|---|:---:|:---:|:---:|:---:|:---:|
| Quick reply buttons | ✅ | ✅ | ✅ | ✅ | ✅ |
| Action buttons | ⚠️ | ✅ | ⚠️ | ⚠️ | ⚠️ |
| Option list | ✅ | ⚠️ | ❌ | ❌ | ❌ |
| Request location | ❌ | ❌ | ❌ | ❌ | ❌ |
| Flows | ✅ | ❌ | ❌ | ❌ | ❌ |

A quick reply button is what comes back as the customer's answer, and it exists on every channel. An
action button is what the device executes: open a link or call. Only WhatsApp Web sends both as you sent
them; on the other channels there is a condition, explained below. Request location is not available
through the API yet.

An option list sent to a Telegram channel is refused right away: the API answers `422` with the message
`[UNSUPPORTED_CHANNEL_TYPE] O canal TELEGRAM nao suporta mensagens do tipo INTERACTIVE_LIST`, and no
message or webhook is created. The Telegram keyboard has no sections, no per-option description and no
button that opens the list. Send the options as quick reply buttons (`INTERACTIVE_BUTTON`).

## Pre-approved template

| Feature | Meta Cloud API | WhatsApp Web | Instagram | Messenger | Telegram |
|---|:---:|:---:|:---:|:---:|:---:|
| Pre-approved template | ✅ WABA | ❌ | ❌ | ✅ Utility | ❌ |

A template is the message Meta approves beforehand so you can write first, outside the window. It only
exists where there is a window: Meta Cloud API and Messenger. On the other channels you write whenever
you want, so it would not be missed.

## The caveats, one by one

### Link on Messenger

The link arrives as a button that opens the `url`, with the `title` as the message and button text
(without `title`, the button says "Abrir link"). `message` and `description` do not show. On Instagram, the
`LINK` type is not sent: put the address inside a [text](/en/messages/send-text). Details in
[Send link](/en/messages/send-link).

### Sticker on Instagram and Messenger

On both, the sticker arrives **as an image**: the customer sees the picture, without sticker behavior. If
the transparent background matters, send artwork already designed to show as an image.

### Location on Messenger

Messenger has no location message. It arrives as **text**, with the place name, the address and the map
link to the coordinates. On Instagram, the location is refused with `422`.

### Action button on Meta Cloud API, Instagram, Messenger and Telegram

An action button is the pair "open a link" and "call". Each channel handles the pair in its own way:

- **Meta Cloud API**: **one link button per message** goes. The call button is not sent.
- **Instagram** and **Telegram**: **only the link works**. The
  [Instagram button template](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/messaging-api/button-template/)
  accepts only link and reply, and the Telegram keyboard has no phone button.
- **Messenger**: the buttons arrive as **quick replies**. The tap sends the button text back as the
  customer reply, instead of opening the link or calling.

**What to do**: write the phone number in the message text when the call button matters, and on Meta
Cloud API send one link per message.

### Option list on WhatsApp Web

The list arrives, but the sections are **flattened**: the customer sees a single list with all the
options, without the section titles. Order the options with that in mind.

### Document on Instagram and Telegram

On **Instagram**, Meta accepts **only PDF** as a file, and only by an `https` URL. It decides by the
`content-type` your server returns, not by the extension: a PDF served as `application/octet-stream`
is refused. Spreadsheets and Base64 are refused too. The file arrives without the name and the caption
you sent.

On **Telegram**, the document goes **by URL only**: Base64 is refused. For PDF, ZIP and GIF, Telegram
itself downloads the file from the URL and shows the name at the end of it; `name` does not change
that. For other formats, like a spreadsheet, the name you sent is the one that shows.

In both cases the API accepts the request with `200`, and the refusal comes later, in the message
status webhook.

**What to do**: on Instagram, send the PDF from an address that answers `application/pdf` and write the
caption in a separate text message. On Telegram, publish the file at a URL that already ends with the
name you want to show.

Source: [sending messages on Instagram](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/messaging-api/)
and [Telegram `sendDocument`](https://core.telegram.org/bots/api#senddocument).

### Store only on Meta Cloud API

Catalog, product and multi-product are only sent through Meta Cloud API, with the catalog connected in
Commerce Manager. On the other channels, WhatsApp Web included, the API accepts the call, but the message
is not sent.

**What to do**: if the store is the important part of your integration, use Meta Cloud API. On the other
channels, send your store link in an [action button](/en/messages/send-interactive-action) or a
[link](/en/messages/send-link).

### Reaction on Telegram

Telegram does not receive reactions through the API: the call is accepted with `200`, and the failure
arrives through the status webhook. On the other four channels the reaction is sent.

### Types not available through the API yet

Request location, order details, order status and polls do not exist in the API yet. Their endpoint pages
warn at the top, and a call with those types is refused with `400`.

### Template on Instagram

This is not a Meta decision, it is a consequence of how we connect: the Graph API `message_templates`
edge exists only on the `Page` node, and Z-API Omni connects Instagram through **Instagram Login**,
which does not expose that edge. Details in [Connect Instagram](/en/connect/instagram).

## When the channel does not accept it: what to send instead

| What you wanted to send | On the channel that does not accept it, send |
|---|---|
| Location | a map link in the text, or a link button to the address |
| Contact | the phone number written in the text |
| Option list | the same items as quick reply buttons, in groups of three |
| Catalog or product | your store link in an action button |
| Form (Flow) | your own web form, opened by a link button |
| Link on Instagram | the address inside a text |
| Reaction on Telegram | a text reply |
| Spreadsheet or other file on Instagram | the file as a PDF, or its link in the text |

## Deleting a sent message

<Warning>
  The API does not delete a message that was already sent, on any channel. Check the text and the
  recipient before sending: once sent, the message stays with the customer.
</Warning>

## Replying with a quote

<Warning>
  The API does not send quoted replies yet, on any channel. The message reaches the customer as a
  regular message, without the excerpt of the original message.
</Warning>

## The 24-hour window, in one sentence

<ChannelSupport type="WINDOW" lang="en" />

The API does not check the window: outside it, it accepts the call and the delivery failure arrives through the status webhook. See [Conversation window](/en/conversation-window).
