## Visão geral

Após [criar um canal](/channels/create-channel) do tipo `META_WHATSAPP`, você precisa **conectá-lo** a um número do WhatsApp Business. Existem duas formas:

- **Pelo painel** — Fluxo guiado diretamente no [Dashboard](https://app.omni.z-api.io)
- **Via SDK + API** — Integre o fluxo de conexão no seu sistema

## Conexão pelo painel

A forma mais simples. Acesse o [Dashboard](https://app.omni.z-api.io), selecione o canal criado e siga o fluxo de conexão guiado.

## Conexão via SDK + API

Use este fluxo quando quiser que o **seu usuário** conecte o canal de dentro do **seu sistema**, sem precisar acessar o painel do {projectName}.

O fluxo tem 3 etapas:

<Steps>
  <Step title="Frontend — Iniciar conexão com o SDK">
    No **frontend** da sua aplicação, use o SDK para iniciar o fluxo de conexão. O SDK vai abrir o processo de autenticação com o WhatsApp e retornar as informações necessárias.

    ```javascript
    import OmniZapi from '@omnizapi/connect';

    const client = OmniZapi.newClient({
      publicKey: 'SUA_PUBLIC_KEY'
    });

    const response = await client.connect({
      channelId: 'ID_DO_CANAL'
    });

    // Envie o response para o seu backend
    ```

    <Tip>
      A `publicKey` pode ser exposta no frontend. Veja mais em [Autenticação](/authentication).
    </Tip>
  </Step>
  <Step title="Frontend → Backend — Enviar dados">
    O SDK retorna um objeto com as informações da conexão. Envie esses dados para o **backend** da sua aplicação:

    ```json
    {
      "wabaId": "428083093730937",
      "phoneId": "123456789012345",
      "code": "ABC123DEF456",
      "coexistence": false
    }
    ```

    | Campo | Tipo | Descrição |
    |---|---|---|
    | `wabaId` | string | ID do WhatsApp Business Account selecionado |
    | `phoneId` | string | ID do número de telefone selecionado |
    | `code` | string | Código de autorização gerado pelo WhatsApp |
    | `coexistence` | boolean | Se o número está em modo de coexistência |
  </Step>
  <Step title="Backend — Finalizar conexão via API">
    No **backend**, chame a API de conexão passando os dados recebidos do frontend:

    `POST /v1/channels/{channelId}/connect`

    ```bash
    curl -X POST https://api.omni.z-api.io/v1/channels/ID_DO_CANAL/connect \
      -H "Content-Type: application/json" \
      -H "Authorization: Bearer SUA_SECRET_KEY" \
      -d '{
        "wabaId": "428083093730937",
        "phoneId": "123456789012345",
        "code": "ABC123DEF456",
        "coexistence": false
      }'
    ```

    <Warning>
      Esta chamada deve ser feita no **backend**, pois utiliza a Secret Key que nunca deve ser exposta no frontend.
    </Warning>
  </Step>
</Steps>

## Canal já conectado

Se o canal já está conectado ao **mesmo número** (`phoneId`), e a Meta confirma que esse número está funcionando, o `connect` é recusado com `409`. Nada muda no canal, e o `code` não é usado:

```json
{
  "error": "channel_already_connected",
  "message": "Channel already connected"
}
```

- Reconheça a recusa pelo campo `error`, que é estável. O `message` é sempre em inglês.
- **Para renovar a conexão do mesmo número**, desconecte antes com [`PUT /v1/channels/{channelId}/disconnect`](/channels/disconnect) e depois chame o `connect` com um `code` novo do SDK. O canal fica fora do ar entre as duas chamadas.
- Se o número caiu na Meta, o `connect` segue normalmente e reconecta o canal.
- Se o integrador mandar outro `phoneId`, o `connect` troca o número, como antes.

<Note>
  **Formas diferentes por canal.** No WhatsApp Oficial, o canal já conectado responde `409` com `channel_already_connected`. No Instagram, no Messenger e no Telegram, a ativação de um canal já ativo continua respondendo `422`, com o erro do provedor no campo `error` (por exemplo, `INSTAGRAM_META_IS_ALREADY_ACTIVATED`).
</Note>

## Fluxo resumido

```
Frontend (SDK)              →  Backend (API)

1. client.connect()
2. Usuário autentica
3. SDK retorna dados ----→  4. POST /v1/channels/{id}/connect
                               com wabaId, phoneId, code, coexistence
                            5. Canal conectado ✓
```

<Note>
  Após a conexão, o canal está pronto para enviar e receber mensagens. Use o `channelId` nos endpoints de [mensagens livres](/messages/introduction) e [templates](/templates/introduction).
</Note>
