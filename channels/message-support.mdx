A promessa do Z-API Omni é uma só: **uma chamada, qualquer canal**. O corpo da requisição é o mesmo
para WhatsApp, Instagram, Messenger e Telegram. Muda o canal no endereço, e pronto.

O que não dá para prometer é que toda plataforma aceite tudo. O Instagram não tem mensagem de
localização. O Telegram não tem botão de ligar. Catálogo de produto só existe onde existe catálogo.
Boa parte desses limites é das plataformas, e esta página é o mapa deles, para você descobrir agora e
não no meio do teste.

## Como ler a tabela

| Marca | O que quer dizer | O que fazer |
|:---:|---|---|
| ✅ | Funciona. O corpo publicado na página do endpoint vale como está. | Enviar. |
| ⚠️ | Funciona **com uma condição**, ou funciona parecido em vez de igual. | Ler a ressalva antes de prometer para o cliente. |
| ❌ | Não sai neste canal: a plataforma não tem o recurso, ou a API ainda não envia este tipo. | Ver o que mandar no lugar, mais abaixo. |
| 🔍 | Não achamos a confirmação na documentação da plataforma. | Tratar como "talvez" e testar antes de depender. |

<Note>
  ⚠️ nunca significa "vai que funciona". Significa que **funciona e nós sabemos em qual condição**, e
  a condição está escrita por extenso aqui embaixo, e também na página de cada endpoint, embaixo da
  tabelinha dele.
</Note>

### O que acontece quando o canal não aceita

Em três casos a API recusa na hora, com `422` `BUSINESS_RULE_VIOLATION`, e a mensagem não é enviada:
**localização no Instagram**, **contato no Instagram** e **lista de opções no Telegram**. Nos outros ❌, a API
aceita a chamada com `200`, a mensagem não é enviada, e a falha chega pelo
[webhook de status](/webhooks/channel-webhooks). Veja [Erros no envio](/messages/introduction#erros-no-envio).

está disponível pela API, em nenhum canal.

## Quando o cliente responde tocando

| Recurso | Meta Cloud API | WhatsApp Web | Instagram | Messenger | Telegram |
|---|:---:|:---:|:---:|:---:|:---:|
| Botões rápidos | ✅ | ✅ | ✅ | ✅ | ✅ |
| Botões de ação | ⚠️ | ✅ | ⚠️ | ⚠️ | ⚠️ |
| Lista de opções | ✅ | ⚠️ | ❌ | ❌ | ❌ |
| Pedir localização | ❌ | ❌ | ❌ | ❌ | ❌ |
| Flows | ✅ | ❌ | ❌ | ❌ | ❌ |

Botão rápido é o que volta como resposta do cliente, e existe em todo canal. Botão de ação é o que o
aparelho executa: abrir um link ou ligar. Só o WhatsApp Web envia os dois como você mandou; nos outros
canais há uma condição, explicada abaixo. Pedir localização ainda não está disponível pela API.

Lista de opções enviada a um canal Telegram é recusada na hora: a API responde `422` com a mensagem
`[UNSUPPORTED_CHANNEL_TYPE] O canal TELEGRAM nao suporta mensagens do tipo INTERACTIVE_LIST` e não cria
mensagem nem dispara webhook. O teclado do Telegram não tem seção, descrição por opção nem o botão que
abre a lista. Mande as opções como botões rápidos (`INTERACTIVE_BUTTON`).

## Template pré-aprovado

| Recurso | Meta Cloud API | WhatsApp Web | Instagram | Messenger | Telegram |
|---|:---:|:---:|:---:|:---:|:---:|
| Template pré-aprovado | ✅ WABA | ❌ | ❌ | ✅ Utility | ❌ |

Template é a mensagem que a Meta aprova antes para você poder escrever primeiro, fora da janela. Só
existe onde existe janela: Meta Cloud API e Messenger. Nos outros canais você escreve quando quiser,
então ele não faria falta.

## As ressalvas, uma por uma

### Link no Messenger

O link chega como um botão que abre a `url`, com o `title` como texto da mensagem e do botão (sem `title`,
o botão diz "Abrir link"). O `message` e a `description` não aparecem. No Instagram, o tipo `LINK` não é
enviado: mande o endereço dentro de um [texto](/messages/send-text). Detalhes em [Enviar link](/messages/send-link).

### Sticker no Instagram e no Messenger

Nos dois, o sticker chega **como imagem**: o cliente vê a figura, sem o comportamento de figurinha. Se o
fundo transparente importa, mande a arte já pensada para aparecer como imagem.

### Localização no Messenger

O Messenger não tem mensagem de localização. Ela chega como **texto**, com o nome do lugar, o endereço e o
link do mapa para as coordenadas. No Instagram, a localização é recusada com `422`.

### Botão de ação na Meta Cloud API, no Instagram, no Messenger e no Telegram

Botão de ação é o par "abrir link" e "ligar". Cada canal trata o par de um jeito:

- **Meta Cloud API**: vai **um botão de link por mensagem**. O botão de ligar não é enviado.
- **Instagram** e **Telegram**: **só o link funciona**. O
  [template de botões do Instagram](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/messaging-api/button-template/)
  aceita apenas link e resposta, e o teclado do Telegram não tem botão de telefone.
- **Messenger**: os botões chegam como **respostas rápidas**. O toque devolve o texto do botão como resposta
  do cliente, em vez de abrir o link ou ligar.

**O que fazer**: escreva o telefone no texto da mensagem quando o botão de ligar for importante, e na Meta
Cloud API mande um link por mensagem.

### Lista de opções no WhatsApp Web

A lista chega, mas as seções são **achatadas**: o cliente vê uma lista única com todas as opções, sem os
títulos das seções. Ordene as opções pensando nisso.

### Documento no Instagram e no Telegram

No **Instagram**, a Meta aceita como arquivo **só PDF**, e só por URL `https`. Ela decide pelo
`content-type` que o seu servidor devolve, não pela extensão: um PDF servido como
`application/octet-stream` é recusado. Planilha e Base64 também são recusados. O arquivo chega sem o
nome e sem a legenda que você mandou.

No **Telegram**, o documento vai **só por URL**: Base64 é recusado. Em PDF, ZIP e GIF, o próprio
Telegram baixa o arquivo pela URL e mostra o nome que está no fim dela; o `name` não muda isso. Nos
outros formatos, como planilha, o nome que você mandou é o que aparece.

Nos dois casos a API aceita o pedido com `200`, e a recusa chega depois, no webhook de status da
mensagem.

**O que fazer**: no Instagram, mande PDF por um endereço que responda `application/pdf` e escreva a
legenda numa mensagem de texto separada. No Telegram, publique o arquivo numa URL que já termine com o
nome que você quer mostrar.

Fonte: [envio de mensagens no Instagram](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/messaging-api/)
e [`sendDocument` do Telegram](https://core.telegram.org/bots/api#senddocument).

### Loja só na Meta Cloud API

Catálogo, produto e multi-produto só são enviados pela Meta Cloud API, com o catálogo conectado no Commerce
Manager. Nos outros canais, inclusive o WhatsApp Web, a API aceita a chamada, mas a mensagem não é enviada.

**O que fazer**: se a loja é a parte importante da sua integração, use a Meta Cloud API. Nos outros canais,
mande o link da loja num [botão de ação](/messages/send-interactive-action) ou num [link](/messages/send-link).

### Reação no Telegram

O Telegram não recebe reação pela API: a chamada é aceita com `200`, e a falha chega pelo webhook de status.
Nos outros quatro canais a reação é enviada.

### Tipos ainda não disponíveis pela API

Pedir localização, detalhes do pedido, status do pedido e enquete ainda não existem na API. As páginas de
endpoint deles avisam no topo, e a chamada com esses tipos é recusada com `400`.

### Template no Instagram

Não é decisão da Meta, é consequência de como conectamos: o `message_templates` do Graph API existe
apenas no node `Page`, e o Z-API Omni conecta o Instagram via **Instagram Login**, que não expõe essa
edge. Detalhes em [Conectar Instagram](/connect/instagram).

## Quando o canal não aceita: o que mandar no lugar

| Você queria mandar | No canal que não aceita, mande |
|---|---|
| Localização | um link de mapa no texto, ou um botão de link para o endereço |
| Contato | o telefone escrito no texto |
| Lista de opções | os mesmos itens como botões rápidos, em grupos de três |
| Catálogo ou produto | o link da sua loja num botão de ação |
| Formulário (Flow) | um formulário web seu, aberto por botão de link |
| Link no Instagram | o endereço dentro de um texto |
| Reação no Telegram | uma resposta em texto |
| Planilha ou outro arquivo no Instagram | o arquivo em PDF, ou o link dele no texto |

## Apagar uma mensagem enviada

<Warning>
  A API não apaga mensagem já enviada, em nenhum canal. Confira o texto e o destinatário antes de
  enviar: depois de enviada, a mensagem fica com o cliente.
</Warning>

## Responder citando uma mensagem

<Warning>
  A API ainda não envia resposta com citação, em nenhum canal. A mensagem chega ao cliente como uma
  mensagem comum, sem o trecho da mensagem original.
</Warning>

## A janela de 24 horas, em uma frase

A API não confere a janela: fora dela, aceita a chamada e a falha de entrega chega pelo webhook de status. Veja [Janela de conversa](/conversation-window).
