## Credenciais da API

O {projectName} trabalha com um par de chaves: **Public Key** e **Secret Key**. Ambas são geradas no menu **Segurança** do painel: [Segurança](https://app.omni.z-api.io/app/security).

---

## Public Key

A Public Key é utilizada pelo SDK de conexão de canais ([`@omnizapi/connect`](https://www.npmjs.com/package/@omnizapi/connect)). Com ela, você pode [conectar canais](/channels/connect-channel) diretamente dentro do seu sistema, sem precisar acessar o painel.

<Note>
  A Public Key pode ser exposta no frontend da sua aplicação, pois ela tem permissões limitadas apenas à conexão de canais.
</Note>

Exemplo de uso:

```javascript
import OmniZapi from '@omnizapi/connect';

const client = OmniZapi.newClient({
  publicKey: 'SUA_PUBLIC_KEY'
});
```

---

## Secret Key

A Secret Key é utilizada para autenticação em todas as APIs do {projectName}. Ela deve ser enviada no header `Authorization` como Bearer token em toda requisição.

<Warning>
  A Secret Key **nunca** deve ser exposta no frontend. Utilize-a apenas no backend da sua aplicação.
</Warning>

Exemplo de uso:

```bash
curl -X GET https://api.omni.z-api.io/whatsapp/businesses \
  -H "Authorization: Bearer SUA_SECRET_KEY"
```

---

## Erros de autenticação

Esta seção vale para a **API Omni** (`https://api.omni.z-api.io/v1/...`). Quando a Secret Key é recusada, a API Omni responde `401` com o header `WWW-Authenticate: Bearer` e o corpo `{"error": "Authorization invalid", "message": <texto>}`. O `message` explica o motivo e o que fazer:

| Motivo | `message` |
|---|---|
| Header ausente ou vazio | `Authorization invalid: the Authorization header is missing or empty. Send the workspace Secret Key as "Authorization: Bearer <secret-key>". See https://developer.omni.z-api.io/en/authentication` |
| Public Key (começa com `pk_`) | `Authorization invalid: this is the Public Key, which only works in the channel connection SDK. Send the workspace Secret Key as "Authorization: Bearer <secret-key>". See https://developer.omni.z-api.io/en/authentication` |
| Fora do formato (ex.: o token do canal) | `Authorization invalid: the value sent is not a Secret Key. Send the workspace Secret Key, generated under Security in the panel, as "Authorization: Bearer <secret-key>". The channel token is not accepted here. See https://developer.omni.z-api.io/en/authentication` |
| Inexistente ou revogada | `Authorization invalid: this Secret Key does not exist or is no longer valid. Copy the current Secret Key under Security in the panel and send it as "Authorization: Bearer <secret-key>". See https://developer.omni.z-api.io/en/authentication` |

O `<secret-key>` é literal: a resposta nunca repete o valor enviado. Trate o erro pelo `error`; o `message` é para leitura e pode mudar.

<Note>
  A Secret Key só aceita o formato `^[a-z0-9_]+$`. O token do canal é hexadecimal em **maiúsculas**, então, se for colado no lugar da Secret Key, cai em **fora do formato**. Um valor com três segmentos separados por ponto segue o caminho OAuth e volta como `{"error": "invalid_token"}`.
</Note>

<Note>
  Os `401` acima são da **API Omni**. Na [rota compatível Z-API](/z-api/introduction) (`/instances/{id}/token/{token}/...`) a autenticação **não mudou**: a recusa vem como `{"error": "Authorization invalid"}`, sem `message` e sem `WWW-Authenticate` — `400` quando o header está ausente ou vazio e `422` quando o formato é inválido ou a chave não existe.
</Note>

## Resumo

| Chave | Uso | Onde usar | Pode expor no frontend? |
|---|---|---|---|
| **Public Key** | [SDK de conexão de canais](/channels/connect-channel) | Frontend ou backend | Sim |
| **Secret Key** | Todas as chamadas de API ([canais](/channels/introduction), [templates](/templates/introduction), [mensagens](/messages/introduction)) | Apenas backend | Não |
