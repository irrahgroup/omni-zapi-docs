## O que é a versão Z-API Compatibilidade?

A versão **Z-API Compatibilidade** responde no formato da Z-API. Quem já integra a Z-API migra para o Z-API Omni trocando a base URL e o header de autenticação, e segue enviando com os mesmos corpos e lendo as mesmas respostas. O endereço é `https://zapi.omni.z-api.io`.

Ela atende **somente canais WhatsApp Oficial** (`META_WHATSAPP`, a API oficial da Meta). As rotas da Z-API que o WhatsApp Oficial não tem, ou que ainda não estão disponíveis, são recusadas com uma resposta clara. A lista completa está em [Limitações e recusas](/z-api/limitations).

<Warning>
  Um envio para um canal de outro tipo (WhatsApp Web, Instagram, Messenger ou Telegram) é recusado com `422`:

  ```json
  { "error": "instance middleware is not META_WHATSAPP" }
  ```

  Um canal WhatsApp Oficial sem assinatura ativa também recebe `422`, com `{ "error": "instance subscription is not active" }`. Para enviar pelos outros canais, use as [rotas de mensagens do Z-API Omni](/messages/introduction).
</Warning>

## O que muda na prática

|  | Z-API | Z-API Omni |
|---|---|---|
| **Base URL** | `https://api.z-api.io` | `https://zapi.omni.z-api.io` |
| **Autenticação** | Header `Client-Token` | Header `Authorization` com a Secret Key, com ou sem `Bearer` ([Autenticação](/z-api/authentication)) |
| **Path** | `/instances/{id}/token/{token}/...` | `/instances/`, `/devices/` ou `/channels/` (equivalentes) |
| **Nomenclatura** | `instance_id` | `channel_id` |
| **Corpo e resposta dos envios** | Formato Z-API | O mesmo formato nas rotas que enviam ([Mensagens](/z-api/messages/introduction)) |
| **Webhooks** | Formato Z-API | Configure `payloadFormat` `Z_API` no webhook do canal ou no webhook padrão ([Webhooks](/webhooks/introduction)) |

### Sobre a nomenclatura

No Z-API Omni, o que antes era chamado de **instância** (`instance_id`) é tratado como **canal** (`channel_id`). O conceito é o mesmo: a conexão com um número de WhatsApp. O termo "canal" é mais abrangente porque o Z-API Omni tem outros canais de mensagem além do WhatsApp.

<Note>
  A API aceita `/instances/`, `/devices/` e `/channels/` no path, com o mesmo comportamento. Quem migra da Z-API pode manter `/instances/`. Em integrações novas, use `/channels/`.
</Note>

Se hoje a sua aplicação faz uma chamada como:

```bash
curl -X POST https://api.z-api.io/instances/SUA_INSTANCIA/token/SEU_TOKEN/send-text \
  -H "Content-Type: application/json" \
  -H "Client-Token: SEU_CLIENT_TOKEN" \
  -d '{"phone": "5511999999999", "message": "Olá!"}'
```

Troque a base URL e o header de autenticação:

```bash
curl -X POST https://zapi.omni.z-api.io/channels/SEU_CANAL/token/SEU_TOKEN/send-text \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer SUA_SECRET_KEY" \
  -d '{"phone": "5511999999999", "message": "Olá!"}'
```

O `SEU_CANAL` é o `id` do canal e o `SEU_TOKEN` é o `token` dele, devolvidos ao [criar o canal](/channels/create-channel) e ao [consultá-lo](/channels/get-channel). A Secret Key é gerada no menu **Segurança** do painel.

## O que a compatibilidade cobre

| Grupo | O que responde |
|---|---|
| [Mensagens](/z-api/messages/introduction) | 42 rotas `send-*` e de pedido. Parte envia, parte é recusada com `422`. Cada rota está na tabela da introdução de mensagens |
| [Instância](/z-api/instance/status) | `status`, `me`, `device` e a fila (`queue`), no formato da Z-API |
| Rotas da Z-API sem equivalente | 149 rotas (grupos, contatos, chats, catálogo, comunidades, canais, perfil comercial, privacidade e etiquetas, entre outras) recusadas com `422` |
| Outras rotas | Método errado responde `405`; rota que não existe responde `404` |

A resposta de cada caso está em [Limitações e recusas](/z-api/limitations).

## Como migrar

<Steps>
  <Step title="Crie sua conta no Z-API Omni">
    Acesse o [Dashboard](https://app.omni.z-api.io) e crie sua conta.
  </Step>
  <Step title="Crie e conecte um canal WhatsApp Oficial">
    Crie um canal do tipo WhatsApp Oficial e conecte o número. Veja [Conectar WhatsApp Oficial](/connect/meta-whatsapp).
  </Step>
  <Step title="Atualize a base URL e a autenticação">
    Troque `https://api.z-api.io` por `https://zapi.omni.z-api.io` e o header `Client-Token` por `Authorization: Bearer SUA_SECRET_KEY`.
  </Step>
  <Step title="Confira as rotas que você usa">
    Compare as rotas da sua integração com [Mensagens](/z-api/messages/introduction) e com [Limitações e recusas](/z-api/limitations). Uma rota recusada responde `422` com o motivo, e nada é enviado.
  </Step>
  <Step title="Configure os webhooks">
    Aponte os webhooks do canal para o seu servidor e use `payloadFormat` `Z_API` para manter o formato. Veja [Webhooks](/webhooks/introduction).
  </Step>
  <Step title="Teste e valide">
    Faça testes de envio e de recebimento antes de trocar o tráfego de produção.
  </Step>
</Steps>
