## Conceituação

Atualiza parcialmente a configuração de um webhook global. Apenas os campos enviados no body são atualizados; os demais permanecem inalterados.

### Atualizar eventos

Se enviar o campo `events`, a lista substitui os eventos existentes e deve conter **somente** eventos da conta: `UPDATE_TEMPLATE_STATUS`, `UPDATE_TEMPLATE_CATEGORY`, os cinco eventos de cobrança (`BILLING_PAYMENT_FAILED`, `BILLING_PAYMENT_RECOVERED`, `BILLING_SUBSCRIPTION_CANCELED`, `BILLING_INSTANCE_SUSPENDED`, `BILLING_INSTANCE_RELEASED`), `ACCOUNT_RESTRICTION` e `CHANNEL_DISCONNECTED` (senão → `422`). Veja [Eventos aceitos](/webhooks/template-webhooks#eventos-aceitos):

```json
{ "events": ["UPDATE_TEMPLATE_STATUS", "UPDATE_TEMPLATE_CATEGORY"] }
```

- A lista não pode ser vazia: `"events": []` retorna `400` com `{"error": "Events cannot be empty when provided"}`. Para manter os eventos, omita o campo.
- Um item nulo, em branco ou com nome que não existe retorna `400` com `{"error": "events contains an unknown or empty event name"}`, e nada é alterado.

<Note>
  **Evento que a API ainda não conhece.** Um webhook pode ter um evento gravado que esta versão da API ainda não conhece, por exemplo um evento novo assinado pelo painel antes de chegar à API. Esse evento não aparece em `events` nas respostas e é mantido quando você troca os eventos: o `PATCH` substitui só os eventos que a API conhece. Um webhook que só tem eventos assim aparece com `events: []`.
</Note>

### Alterar a URL

A nova `url` segue as mesmas regras da criação (veja [URL do webhook](/webhooks/introduction#url-do-webhook)). Ela só é conferida quando muda: um `PATCH` sem `url`, ou com a URL já gravada, não é recusado por ela.

### Assinatura HMAC

`signing: true` gera um novo `secret` (retornado apenas nesta resposta); `signing: false` remove a assinatura.

<Warning>
  O novo `secret` é retornado **apenas nesta resposta**. Armazene-o antes de fechar a sessão.
</Warning>

<Warning>
  `signing: true` rotaciona o secret **toda vez**, inclusive quando a assinatura já estava habilitada e você só queria mudar outro campo no mesmo request. Para não rotacionar, **omita** o campo `signing`.
</Warning>

Para validar a assinatura, veja [Assinatura HMAC](/webhooks/signature).

### Desabilitar temporariamente

```json
{ "status": "DISABLED" }
```

Para reativar, envie `{ "status": "ENABLED" }`.

Um `status` diferente de `ENABLED` e `DISABLED` retorna `400` com `{"error": "status must be one of [ENABLED, DISABLED]"}`.

### Formato de entrega: use `DEFAULT`

O webhook global é entregue no formato `DEFAULT`. Envie `payloadFormat` `DEFAULT` ou omita o campo.

| Caso | Resposta |
|---|---|
| `events` com `ACCOUNT_RESTRICTION` e `payloadFormat` `Z_API` ou `CHATWOOT` | `422` com `{"error": "ACCOUNT_RESTRICTION only supports DEFAULT payload format"}` |
| O webhook ficaria com eventos da plataforma (cobrança ou `CHANNEL_DISCONNECTED`) em formato diferente de `DEFAULT` | `422` com `{"error": "Platform events are delivered only in DEFAULT payload format"}` |

A conferência usa o estado final que o pedido deixaria: os eventos enviados (ou os já gravados, se `events` for omitido) e o formato enviado (ou o já gravado). Nada é alterado quando o pedido é recusado.

<Note>
  Após a alteração, o roteamento pode levar até ~5 min para refletir (TTL de cache).
</Note>
