## O que são webhooks?

Webhooks são notificações HTTP que o {projectName} envia ao seu servidor quando eventos acontecem — como uma mensagem recebida, status de entrega, ou uma atualização de template.

Em vez de o seu sistema consultar a API periodicamente (polling), o {projectName} **envia os eventos para você** assim que acontecem.

```
Evento acontece → Z-API Omni → POST para sua URL → Seu sistema processa
```

<Note>
  Qualquer secret key válida de um workspace ativo pode gerenciar webhooks: de canal, padrão e global. Não é preciso nenhuma role específica na conta. Se o workspace não estiver ativo, as chamadas de webhook retornam `422` com `{"error": "Webhook management requires an active workspace"}`.
</Note>

## Formatos de payload

O {projectName} suporta três formatos de payload:

| Formato | Descrição |
|---|---|
| `DEFAULT` | Formato padrão do Z-API Omni |
| `Z_API` | Formato compatível com a Z-API — mantém a estrutura que suas integrações já tratam, ideal para quem está migrando |
| `CHATWOOT` | Formato esperado pelo Chatwoot, para plugar o canal direto na caixa de entrada dele |

<Note>
  O [webhook global](/webhooks/template-webhooks) é entregue em `DEFAULT`: use sempre `DEFAULT` nele. Com `ACCOUNT_RESTRICTION` ou com os eventos da plataforma (cobrança e `CHANNEL_DISCONNECTED`), outro formato responde `422`. O webhook padrão não aceita `CHATWOOT`.
</Note>

## URL do webhook

Ao criar um webhook, e ao trocar a URL de um webhook existente, o {projectName} confere a `url` antes de gravar. As regras valem para os três tipos de webhook.

| Regra | Se não for atendida |
|---|---|
| URL absoluta, com `http` ou `https`, de até 2048 caracteres | `400` com `{"error": "Invalid webhook URL: use an absolute http or https URL up to 2048 characters"}` |
| O host existe no DNS e resolve só para endereços públicos | `400` com `{"error": "Webhook URL not allowed: the host must resolve only to public addresses"}` |

O host é recusado quando:

- é um IP que não é público: rede privada, loopback, link-local (inclusive o endereço de metadados de nuvem `169.254.169.254`), CGNAT, multicast ou faixa reservada, em IPv4 ou IPv6;
- é um nome que resolve para um desses endereços. Basta um endereço não público entre os que o nome devolve;
- é `localhost`, termina em `.localhost` ou `.internal`, ou é um nome sem ponto, como `https://servidor/webhook`;
- é um IPv4 escrito fora da forma usual de quatro números decimais, como `http://2130706433/`;
- não existe no DNS ou não tem endereço.

Se o DNS não responder a tempo, a resposta é `503` com `{"error": "Could not verify the webhook URL now, try again"}`. Nada é gravado: tente de novo.

<Note>
  `http` continua aceito, mas prefira `https`: com `http`, o corpo do evento e os headers de autenticação trafegam sem criptografia.
</Note>

<Note>
  Na atualização, a `url` só é conferida quando muda. Um `PATCH` sem `url`, ou com a mesma URL já gravada, não é recusado por ela: um webhook antigo cuja URL hoje seria recusada continua podendo ser desabilitado, alterado em outros campos ou excluído.
</Note>

## Autenticação do webhook

Você pode configurar como o {projectName} se autentica ao chamar sua URL:

| Tipo | Como funciona |
|---|---|
| `NONE` | Sem autenticação (não recomendado em produção) |
| `BEARER` | Envia `Authorization: Bearer <token>` |
| `API_KEY` | Envia uma chave de API configurada |
| `BASIC` | HTTP Basic Authentication (`username:password`) |
| `CUSTOM_HEADER` | Envia um header customizado com nome e valor definidos por você |

## Assinatura HMAC

Para garantir que as requisições recebidas são realmente do {projectName} e não foram adulteradas, habilite a assinatura HMAC configurando `signing: true` ao criar o webhook.

Quando habilitado:
- Um `secret` de 64 caracteres hexadecimais é gerado e retornado **apenas uma vez** na criação/atualização.
- Cada requisição enviada ao seu webhook traz o header `x-webhook-signature`, no formato `t={unix_timestamp},v1={hmac_sha256_hex}`.
- Você verifica a assinatura no seu servidor usando o `secret` armazenado.

<Warning>
  A assinatura **não** é o HMAC apenas do corpo. Ela é calculada sobre uma string canônica de cinco campos, da qual o corpo é o último. Veja [Assinatura HMAC](/webhooks/signature) para a string exata, um exemplo completo e código de validação pronto.
</Warning>

<Warning>
  O `secret` é exibido **apenas** na resposta de criação ou de atualização com `signing: true`. Armazene-o com segurança — ele não pode ser recuperado depois.
</Warning>
