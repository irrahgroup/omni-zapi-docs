## Conceituação

Envia uma mensagem com uma lista de opções agrupadas em seções. O cliente toca no botão, abre a lista e
escolhe uma linha. O campo `content.type` deve ser `INTERACTIVE_LIST`.

É o formato para quando as opções não cabem em botões: cardápio, catálogo de serviços, horários, unidades.
Até 3 opções, prefira os [botões de resposta rápida](/messages/send-interactive-button), que exigem um toque
a menos.

## Campos

| Campo | O que vai nele |
|---|---|
| `body.message` | O texto da mensagem. Obrigatório |
| `action.message` | O texto do botão que abre a lista. Obrigatório |
| `attachments` | As seções da lista, uma por item. Obrigatório, com ao menos uma seção |
| `attachments[].title` | O título da seção. Obrigatório quando há mais de uma seção |
| `attachments[].list` | As linhas da seção, ao menos uma |
| `attachments[].list[].id` | O identificador da linha, escolhido por você. Obrigatório |
| `attachments[].list[].title` | O texto da linha. Obrigatório |
| `attachments[].list[].description` | Um texto de apoio abaixo da linha. Opcional |
| `header.message` | O cabeçalho, só texto. Opcional |
| `footer.message` | O rodapé. Opcional |

Os nomes são os desta página, e não os da Meta Cloud API: o texto do botão vai em `action.message`, e as
linhas, em `attachments[].list`. Um corpo com `button` e `sections` é recusado por falta de `action.message`.

## Limites na Meta Cloud API

No canal Meta Cloud API, a API confere os limites da Meta antes de aceitar o envio:

| Campo | Limite |
|---|---|
| `body.message` | 1024 caracteres |
| `header.message` | 60 caracteres |
| `footer.message` | 60 caracteres |
| `action.message` | 20 caracteres |
| Linhas | **10 no total, somando todas as seções** |
| `attachments[].title` | 24 caracteres |
| `attachments[].list[].id` | 200 caracteres, sem repetir na mesma seção |
| `attachments[].list[].title` | 24 caracteres |
| `attachments[].list[].description` | 72 caracteres |

<Warning>
  O limite de linhas é **no total**, não por seção. Duas seções com seis linhas cada são recusadas: o máximo
  são dez linhas, distribuídas entre as seções que você quiser.
</Warning>

O mesmo `id` pode aparecer em seções diferentes. Na mesma seção, não.

## Quando a API recusa a lista

Se falta um campo obrigatório ou um limite é ultrapassado, a API responde `400` com `code`
`VALIDATION_ERROR`, e a mensagem não é enviada. O `message` nomeia o primeiro campo com problema:

```json
{
  "timestamp": "2026-10-22T14:00:00.123Z",
  "code": "VALIDATION_ERROR",
  "message": "Field 'content.action.message': is required for message type INTERACTIVE_LIST"
}
```

A resposta traz só o primeiro problema. Corrigido esse, a próxima chamada pode apontar outro.

| Caso | `message` |
|---|---|
| Sem o texto do botão | `Field 'content.action.message': is required for message type INTERACTIVE_LIST` |
| Seção com `list` vazia | `Field 'content.attachments[0].list': must have at least one row` |
| Mais de 10 linhas | `Field 'content.attachments': must have at most 10 rows across all sections` |
| Corpo acima do limite | `Field 'content.body.message': must be at most 1024 characters` |
| `id` repetido na seção | `Field 'content.attachments[0].list[1].id': must be unique within the section` |

## No WhatsApp Web

Os campos obrigatórios são os mesmos, e os limites da tabela acima não são conferidos. As linhas de todas as
seções aparecem numa lista só, sem o título da seção, e o rodapé não é enviado.

## A resposta do cliente

No canal Meta Cloud API, a escolha do cliente chega ao seu [webhook](/webhooks/payloads) como uma mensagem
recebida. O conteúdo fica em `contents[0]`:

| Campo | O que traz |
|---|---|
| `type` | `BUTTON` |
| `title` | O `title` da linha escolhida |
| `description` | A `description` da linha escolhida |
| `external_information.list_reply_id` | O `id` que você enviou na linha |

Identifique a opção pelo `id`, sem depender do texto exibido, que pode mudar sem quebrar a integração.

<Note>
  Detalhes da regra da Meta Cloud API em [janela de conversa](/conversation-window). Veja [o que cada canal aceita](/channels/message-support) para todos os canais.
</Note>

<Note>
  Com o canal desconectado, a API recusa o envio com `422` e `subCode` `CHANNEL_DISCONNECTED`, e a mensagem não é enviada. Veja [Erros no envio](/messages/introduction#erros-no-envio).
</Note>

<Note>
  A rota `POST /v1/channels/{channelId}/send-option-list` aceita o mesmo corpo desta página e dá a mesma resposta. Nela, `content.type` é opcional e, se vier, tem de ser `INTERACTIVE_LIST`. Com outro valor, a API responde `400` `{"error": "invalid_request", "field": "content.type", "message": "content.type must be INTERACTIVE_LIST on /send-option-list; leave it out, or send other types with POST /v1/channels/{id}/messages"}`, e a mensagem não é enviada. Veja [Rotas por tipo](/messages/introduction#rotas-por-tipo).
</Note>
