## Um código, cinco canais

Você **não** escreve um fluxo por canal. O SDK lê o tipo do canal e despacha o fluxo certo sozinho:

```javascript
import OmniZapi from '@omnizapi/connect';

const client = OmniZapi.newClient({ publicKey: 'SUA_PUBLIC_KEY' });

// Igual para WhatsApp, Instagram, Messenger e Telegram; o WhatsApp Web pede também o getQRCode
const response = await client.connect({ channelId: 'ID_DO_CANAL' });

if (response.success) {
  await fetch('/meu-backend/conectar-canal', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(response),
  });
}
```

<Note>
  O WhatsApp Web pede também a função `getQRCode`, que busca o QR Code no seu backend. Os outros canais a ignoram, então você pode passá-la sempre. Veja [WhatsApp Web](/connect/whatsapp-web).
</Note>

O tipo vem do canal, não da chamada. Você define o tipo em [Criar canal](/channels/create-channel) e o SDK resolve o resto.

## O que acontece por dentro

<Steps>
  <Step title="O SDK consulta o canal">
    Ele chama [`GET /instances/{channelId}/sdk-info`](/channels/sdk-info) para descobrir o tipo do canal, o app da Meta correspondente e as [origens liberadas](/channels/sdk-info).
  </Step>
  <Step title="Despacha o fluxo do tipo">
    Cada tipo tem um caminho próprio de autorização — OAuth da Meta, QR Code ou token de bot.
  </Step>
  <Step title="Devolve os dados da conexão">
    O objeto de retorno muda conforme o canal. Veja a tabela abaixo.
  </Step>
  <Step title="Você finaliza no backend">
    Envie o retorno para o seu backend e chame a rota de finalização do tipo do canal, com a Secret Key. Cada canal tem a sua rota: veja a seção Finalizar a conexão no backend, abaixo.
  </Step>
</Steps>

## Fluxo de autorização por canal

|  | Meta Cloud API | WhatsApp Web | Instagram | Messenger | Telegram |
|---|---|---|---|---|---|
| **Como autoriza** | Embedded Signup da Meta | QR Code | OAuth do Instagram | OAuth do Facebook + escolha da página | Token do bot |
| **Página** | [Meta WhatsApp](/connect/meta-whatsapp) | [WhatsApp Web](/connect/whatsapp-web) | [Instagram](/connect/instagram) | [Messenger](/connect/messenger) | [Telegram](/connect/telegram) |

## O retorno muda por canal

Todos devolvem `success`, `channelId` e `type`, o tipo do canal. O resto depende do tipo:

| Campo | Meta Cloud API | WhatsApp Web | Instagram | Messenger | Telegram |
|---|:---:|:---:|:---:|:---:|:---:|
| `code` | ✅ | ❌ | ✅ | ✅ | ❌ |
| `wabaId` | ✅ | ❌ | ❌ | ❌ | ❌ |
| `phoneId` | ✅ | ❌ | ❌ | ❌ | ❌ |
| `coexistence` | ✅ | ❌ | ❌ | ❌ | ❌ |
| `redirectUri` | ❌ | ❌ | ✅ | ✅ | ❌ |
| `accessToken` | ❌ | ❌ | ✅ | ✅ | ❌ |
| `pageId` | ❌ | ❌ | ❌ | ✅ | ❌ |
| `botToken` | ❌ | ❌ | ❌ | ❌ | ✅ |

## Finalizar a conexão no backend

Mande o objeto inteiro para o seu backend. Lá, use o campo `type` para escolher a rota de finalização e monte o corpo a partir do retorno do SDK, sempre com a Secret Key:

|  | Meta Cloud API | WhatsApp Web | Instagram | Messenger | Telegram |
|---|---|---|---|---|---|
| **Rota de finalização** | [`POST /v1/channels/{channelId}/connect`](/channels/connect-channel) | Sem finalização | [`POST /v1/channels/{channelId}/activate-instagram`](/channels/activate-instagram) | [`POST /v1/channels/{channelId}/activate-messenger`](/channels/activate-messenger) | [`POST /v1/channels/{channelId}/activate-telegram`](/channels/activate-telegram) |
| **Corpo, a partir do retorno do SDK** | `code`, `wabaId`, `phoneId` e `coexistence` | O canal conecta quando o QR Code é lido. Confira com [`GET /v1/channels/{channelId}/zapi/status`](/channels/zapi-status) | `{"code", "redirectUri"}` | `{"pageId", "accessToken", "redirectUri"}`. A página e o `accessToken` vêm de [Listar páginas do Messenger](/channels/list-messenger-pages); veja [Messenger](/connect/messenger) | `{"token": "<botToken do SDK>"}`. O campo se chama `token`, não `botToken` |

<Warning>
  `POST /v1/channels/{channelId}/connect` é só do WhatsApp Oficial. Com o retorno de outro canal, ele responde `400` com `{"error":"wabaId is required"}`.
</Warning>

<Warning>
  A conexão só funciona a partir de domínios liberados, e o SDK falha em silêncio quando a origem não está na lista. Leia [Origens do SDK](/channels/sdk-info) antes de integrar.
</Warning>

## Sem o SDK

O SDK existe porque cada canal tem um fluxo de autorização diferente na plataforma de origem, e todos exigem uma janela do navegador. Se você precisar montar isso na mão, cada página de canal descreve a URL de autorização, os escopos e os parâmetros usados.
