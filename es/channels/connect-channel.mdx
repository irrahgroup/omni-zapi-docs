## Visión general

Después de [crear un canal](/es/channels/create-channel) del tipo `META_WHATSAPP`, tienes que **conectarlo** a un número de WhatsApp Business. Hay dos formas de hacerlo:

- **Desde el panel**: Flujo guiado directamente en el [Panel](https://app.omni.z-api.io)
- **Con el SDK + API**: Integra el flujo de conexión en tu sistema

## Conexión desde el panel

Es la forma más sencilla. Entra en el [Panel](https://app.omni.z-api.io), selecciona el canal que creaste y sigue el flujo de conexión guiado.

## Conexión con el SDK + API

Usa este flujo cuando quieras que **tu usuario** conecte el canal desde **tu propio sistema**, sin necesidad de entrar al panel de {projectName}.

El flujo consta de 3 etapas:

<Steps>
  <Step title="Frontend: Iniciar la conexión con el SDK">
    En el **frontend** de tu aplicación, usa el SDK para iniciar el flujo de conexión. El SDK abrirá el proceso de autenticación con WhatsApp y devolverá la información necesaria.

    ```javascript
    import OmniZapi from '@omnizapi/connect';

    const client = OmniZapi.newClient({
      publicKey: 'SU_PUBLIC_KEY'
    });

    const response = await client.connect({
      channelId: 'ID_DEL_CANAL'
    });

    // Envía el response a tu backend
    ```

    <Tip>
      La `publicKey` se puede exponer en el frontend. Más información en [Autenticación](/es/authentication).
    </Tip>
  </Step>
  <Step title="Frontend → Backend: Enviar los datos">
    El SDK devuelve un objeto con la información de la conexión. Envía esos datos al **backend** de tu aplicación:

    ```json
    {
      "wabaId": "428083093730937",
      "phoneId": "123456789012345",
      "code": "ABC123DEF456",
      "coexistence": false
    }
    ```

    | Campo | Tipo | Descripción |
    |---|---|---|
    | `wabaId` | string | ID de la cuenta de WhatsApp Business seleccionada |
    | `phoneId` | string | ID del número de teléfono seleccionado |
    | `code` | string | Código de autorización generado por WhatsApp |
    | `coexistence` | boolean | Indica si el número está en modo de coexistencia |
  </Step>
  <Step title="Backend: Finalizar la conexión mediante la API">
    En el **backend**, llama a la API de conexión enviando los datos recibidos del frontend:

    `POST /v1/channels/{channelId}/connect`

    ```bash
    curl -X POST https://api.omni.z-api.io/v1/channels/ID_DEL_CANAL/connect \
      -H "Content-Type: application/json" \
      -H "Authorization: Bearer SU_SECRET_KEY" \
      -d '{
        "wabaId": "428083093730937",
        "phoneId": "123456789012345",
        "code": "ABC123DEF456",
        "coexistence": false
      }'
    ```

    <Warning>
      Esta llamada debe hacerse en el **backend**, ya que utiliza la Secret Key, que nunca debe exponerse en el frontend.
    </Warning>
  </Step>
</Steps>

## Canal ya conectado

Si el canal ya está conectado al **mismo número** (`phoneId`) y Meta confirma que ese número funciona, el `connect` se rechaza con `409`. Nada cambia en el canal y el `code` no se usa:

```json
{
  "error": "channel_already_connected",
  "message": "Channel already connected"
}
```

- Reconozca el rechazo por el campo `error`, que es estable. El `message` siempre está en inglés.
- **Para renovar la conexión del mismo número**, desconecte antes con [`PUT /v1/channels/{channelId}/disconnect`](/es/channels/disconnect) y luego llame al `connect` con un `code` nuevo del SDK. El canal queda fuera de servicio entre las dos llamadas.
- Si el número se cayó en Meta, el `connect` sigue normalmente y reconecta el canal.
- Si envía otro `phoneId`, el `connect` cambia el número, como antes.

## Flujo resumido

```
Frontend (SDK)              →  Backend (API)

1. client.connect()
2. El usuario se autentica
3. El SDK devuelve datos -→  4. POST /v1/channels/{id}/connect
                               con wabaId, phoneId, code, coexistence
                            5. Canal conectado ✓
```

## Respuesta

Esta ruta es solo de WhatsApp Oficial y no requiere ENTERPRISE. La API valida solo el `wabaId`; `code` y `phoneId` son necesarios para completar la conexión. Si todo va bien, responde `200`, y `success` tiene el mismo valor que `connected`:

```json
{
  "phoneId": "123456789012345",
  "connected": true,
  "success": true,
  "isCoexistence": false,
  "phoneConnected": "5511999999999",
  "businessName": "Minha Empresa"
}
```

## Errores

| Estado | Cuerpo | Cuándo |
|---|---|---|
| `400` | `{"error":"wabaId is required"}` | Cuerpo sin `wabaId`, por ejemplo con el resultado del SDK de otro canal |
| `400` | `{"error":"Authorization invalid"}` | Secret Key ausente, mal formada o inexistente |
| `404` | `{"error":"Instance not found"}` | Canal inexistente o de otro workspace |
| `409` | `{"error":"channel_already_connected","message":"Channel already connected"}` | El mismo número ya está conectado |
| `502` | `{"error":"integration_unavailable", ...}` | Falla de integración; vuelve a intentarlo en unos instantes |
| `504` | `{"error":"outcome_unknown", ...}` | El resultado no se conoce; revisa el estado del canal con [Consultar canal](/es/channels/get-channel) antes de repetir |

<Note>
  Una vez establecida la conexión, el canal está listo para enviar y recibir mensajes. Usa el `channelId` en los endpoints de [mensajes libres](/es/messages/introduction) y [plantillas](/es/templates/introduction).
</Note>
