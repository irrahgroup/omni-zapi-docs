## Conceptos

Crea un canal nuevo. Una vez creado, el canal debe conectarse (desde el panel o con el SDK) para poder empezar a enviar y recibir mensajes.

El canal nace en `TRIAL` por 2 días; para mantenerlo, suscríbelo con [Suscribir canal](/es/channels/subscribe-channel).

El `id` devuelto es el `channelId` que se usa en todas las llamadas a la API.

### Token del canal

Cuando la creación se autentica con la **Secret Key** del workspace, la respuesta `201` también trae el `token` del canal:

```json
{
  "id": "019E4C54B1B375A28970B605CA9B03C3",
  "token": "F1B29C3D4E5A6B7C8D9E0F1A2B3C4D5E"
}
```

Es el mismo token que [Consultar canal](/es/channels/get-channel) devuelve con la Secret Key. El token identifica el canal en las rutas con el formato de Z-API, con el token en la ruta. Las rutas de esta referencia usan la Secret Key en el header Authorization.

Crear canal acepta solo la Secret Key.

Las respuestas de error no cambian y no traen token.

<Note>
  Lo mismo vale para las rutas equivalentes `POST /v1/instances` y `POST /v1/devices`.
</Note>

### Tipos disponibles

| Tipo | Plataforma |
|---|---|
| `META_WHATSAPP` | WhatsApp (API Oficial de Meta) |
| `Z_API_WHATSAPP` | WhatsApp Web |
| `META_INSTAGRAM` | Instagram |
| `META_MESSENGER` | Messenger |
| `BOT_TELEGRAM` | Telegram |

### Nombre único en el workspace

El nombre del canal es único entre los canales activos del workspace. Si otro canal activo ya usa el mismo nombre, la creación se rechaza con `409`, y no se crea ningún canal:

```json
{
  "error": "channel_name_in_use",
  "message": "A channel with this name already exists in this workspace. Pick another one."
}
```

- La comparación no distingue mayúsculas e ignora los espacios del inicio y del final: `Ventas`, `ventas` y ` Ventas ` son el mismo nombre. El canal se guarda sin esos espacios.
- Los acentos y los espacios internos diferencian: `Ventás` y `Ven  tas` son otros nombres.
- El tipo de canal no importa: un `META_WHATSAPP` y un `BOT_TELEGRAM` no pueden tener el mismo nombre en el workspace.
- Un canal cancelado y todavía no eliminado sigue ocupando el nombre. Un canal eliminado libera el nombre.
- Reconozca el rechazo por el campo `error`, que es estable. El `message` siempre está en inglés y se puede mostrar al usuario.

<Note>
  Los canales creados antes de esta regla no cambian, incluso los que tienen el nombre repetido. Si tu integración crea canales con nombres repetidos, trata el `409` eligiendo otro nombre.
</Note>

### Errores

| Estado | Cuerpo | Cuándo |
|---|---|---|
| `400` | `{"error":"Authorization invalid"}` | Secret Key ausente, mal formada o inexistente |
| `400` | `{"error":"203.0.113.10 not allowed"}` | IP fuera de la [lista de IPs](/es/security/ip-restriction) |
| `400` | `{"error":"type is required"}` | Cuerpo sin `type` |
| `400` | `{"error":"Required request body is missing"}` | `type` fuera de la lista de tipos, o JSON inválido |
| `409` | `{"error":"channel_name_in_use", ...}` | Nombre ya usado por otro canal activo |
| `422` | `{"error":"channel_type_not_enabled","message":"Z_API_WHATSAPP channel is not enabled for this workspace. Contact support."}` | WhatsApp Web no habilitado en el workspace |
| `422` | `{"error":"Channel creation requires ENTERPRISE role"}` | Cuenta sin el rol ENTERPRISE |
| `502` | `{"error":"integration_unavailable", ...}` | Falla de integración; vuelve a intentarlo en unos instantes |
| `504` | | La creación no respondió a tiempo; antes de repetir, revisa en [Listar canales](/es/channels/list-channels) si el canal se creó |
