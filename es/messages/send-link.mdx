## Conceptos

Envía un texto con la vista previa de un enlace: título, descripción e imagen. Los datos van en el objeto `content.body`.

El campo `content.type` debe ser `LINK`.

## Cuerpo de la petición

```json
{
  "recipient": {
    "identifier": "5511999999999"
  },
  "content": {
    "type": "LINK",
    "body": {
      "message": "Veja a nossa nova coleção: https://exemplo.com/colecao",
      "url": "https://exemplo.com/colecao",
      "title": "Coleção de verão",
      "description": "Peças novas toda semana",
      "thumbnail": "https://exemplo.com/capa.jpg"
    }
  }
}
```

## Campos

| Campo | Obligatorio | Descripción |
|---|:---:|---|
| `content.body` | sí | Datos del mensaje |
| `content.body.message` | no | Texto del mensaje |
| `content.body.url` | no | URL del enlace |
| `content.body.title` | no | Título de la vista previa |
| `content.body.description` | no | Descripción de la vista previa |
| `content.body.thumbnail` | no | URL de la imagen de la vista previa |
| `content.body.linkType` | no | Formato de la vista previa. La API reenvía el valor al canal sin revisarlo |

<Note>
  Sin `content.body`, la API responde `400` con `code` `VALIDATION_ERROR` y `message` `"Field 'content.body': is required for message type LINK"`, y el mensaje no se envía.
</Note>

<Note>
  La API no rechaza este tipo por canal antes del envío. El `200` confirma que la API aceptó el mensaje, no que el canal lo entregó: sigue el estado por el [webhook](/es/webhooks/payloads). Consulta [qué acepta cada canal](/es/channels/message-support).
</Note>

<Note>
  Con el canal desconectado, la API rechaza el envío con `422` y `subCode` `CHANNEL_DISCONNECTED`, y el mensaje no se envía. Consulta [Errores al enviar](/es/messages/introduction#errores-al-enviar).
</Note>

<Note>
  Cuando el envío es aceptado, la API responde `200` con el `messageId`. Consulta [Respuesta de la API](/es/messages/introduction#respuesta-de-la-api).
</Note>

<Note>
  La ruta `POST /v1/channels/{channelId}/send-link` acepta el mismo cuerpo de esta página y da la misma respuesta. En ella, `content.type` es opcional y, si lo envías, debe ser `LINK`. Con otro valor, la API responde `400` `{"error": "invalid_request", "field": "content.type", "message": "content.type must be LINK on /send-link; leave it out, or send other types with POST /v1/channels/{id}/messages"}`, y el mensaje no se envía. Consulta [Rutas por tipo](/es/messages/introduction#rutas-por-tipo).
</Note>
