## Envelope del evento

Toda petición enviada a tu webhook tiene la siguiente estructura de nivel superior:

```json
{
  "message": { ... },
  "messageEventType": "NEW_MESSAGE"
}
```

| Campo | Tipo | Descripción |
|---|---|---|
| `message` | object | Objeto completo del mensaje |
| `messageEventType` | string | Tipo de evento: actualmente `"NEW_MESSAGE"` para todos los eventos de mensaje |

## Campos comunes del mensaje

Todos los payloads comparten los mismos campos dentro del objeto `message`, con independencia del tipo de contenido:

| Campo | Tipo | Descripción |
|---|---|---|
| `_id` | string | ID único del mensaje |
| `tenant` | string | ID del workspace |
| `tenant_owner` | string | Correo electrónico del propietario del workspace |
| `channel_id` | string | ID del canal que recibió o envió el mensaje |
| `chat_id` | string | Identificador de la conversación en el canal, en el formato `<channel_id>=<identificador>`. Presente en los canales WhatsApp de la API oficial de Meta. Consulta la sección Identificador de la conversación |
| `created_by` | string | Origen interno del mensaje |
| `created` | number | Timestamp de creación (epoch en ms) |
| `metadata.from_api` | boolean | `true` cuando se envió mediante la API |
| `metadata.from_me` | boolean | `true` cuando lo envió el negocio; `false` cuando se recibió del contacto |
| `metadata.middleware` | string | Plataforma del canal (p. ej.: `"META_WHATSAPP"`) |
| `metadata.forwarded` | boolean | `true` si el mensaje fue reenviado |
| `sender.identifier` | string | Identificador de quien lo envió |
| `sender.name` | string | Nombre de quien lo envió |
| `recipient.identifier` | string | Teléfono del destinatario (código de país + prefijo + número) |
| `contents` | array | Contenidos textuales e interactivos del mensaje |
| `attachments` | array | Adjuntos multimedia (imagen, audio, vídeo, sticker) |
| `webhook_processed` | boolean | Control interno de procesamiento |

## Identificador de la conversación (`chat_id`)

En los canales WhatsApp de la API oficial de Meta, el mensaje recibido, el mensaje enviado desde el teléfono del negocio y los callbacks de estado traen el campo `chat_id`, formado por el canal y el participante de la conversación.

| Parte | Valor |
|---|---|
| Antes del `=` | El `channel_id` del canal, el mismo campo `channel_id` del payload y de la API |
| Después del `=` | El identificador del participante de la conversación. En el mensaje enviado desde el teléfono del negocio y en los callbacks de estado, es el teléfono del contacto (código de país + código de área + número), igual a `recipient.identifier`. En el mensaje recibido, es el número del canal |

Ejemplo de callback de estado:

```json
{
  "message": {
    "_id": "019E6F1A93FE78DCB54332F9FF0CCAE7",
    "channel_id": "019E4C54B1B375A28970B605CA9B03C3",
    "chat_id": "019E4C54B1B375A28970B605CA9B03C3=5511999990000",
    "recipient": {
      "@class": ".Recipient",
      "identifier": "5511999990000",
      "name": "5511999990000"
    },
    "contents": [
      {
        "type": "MessageStatusCallback",
        "phone": "5511999990000",
        "state": { "@class": ".Sent", "name": "SENT" }
      }
    ]
  }
}
```

- En el mensaje recibido, el `chat_id` es el mismo en todos los mensajes que recibe el canal, porque la parte después del `=` es el número del canal. No agrupes mensajes recibidos por `chat_id`; usa `sender.identifier`.
- El campo no viene en todos los eventos. El mensaje enviado por la API, por ejemplo, no trae `chat_id`.
- Para obtener el teléfono del contacto, usa `recipient.identifier` (mensaje enviado y estado) o `sender.identifier` (mensaje recibido). No extraigas el teléfono del `chat_id`.

## Mensajes de grupo (WhatsApp Web)

En los canales WhatsApp Web (`metadata.middleware` igual a `"Z_API_WHATSAPP"`), un mensaje intercambiado en un grupo trae la identificación del grupo en el `internal_information` de cada elemento de `contents` y `attachments`:

| Campo | Tipo | Descripción |
|---|---|---|
| `internal_information.group_id` | string | ID del grupo, en el formato `120363430845284251-group`. Los grupos antiguos pueden venir en el formato `556592929755-1499690308` |
| `internal_information.group_name` | string | Nombre del grupo |
| `internal_information.participant_lid` | string | LID de quien envió el mensaje en el grupo, cuando la plataforma lo informa |

En un mensaje recibido de un grupo, `sender.identifier` es el teléfono de quien escribió, no el del grupo. Los dos campos de grupo también aparecen cuando el mensaje se envía al grupo desde el propio número del canal (`metadata.from_me: true`). Los mensajes individuales no tienen `group_id` ni `group_name`.

```json
"contents": [
  {
    "@class": ".TextContent",
    "internal_information": {
      "group_id": "120363430845284251-group",
      "group_name": "Equipo de ventas"
    },
    "message": "¡Buenos días a todos!",
    "type": "TEXT"
  }
]
```

## Respuesta citada (Meta Cloud API)

En un mensaje enviado como [respuesta citada](/es/messages/introduction#responder-citando-un-mensaje), cada elemento de `contents` y de `attachments` trae el mensaje citado:

| Campo | Tipo | Descripción |
|---|---|---|
| `message_id_reply` | string | `_id` del mensaje citado, incluso cuando la referencia enviada fue el `identifier` de un contenido |
| `integration_id_reply` | string | Id del mensaje citado en Meta (`wamid`) |

```json
"contents": [
  {
    "@class": ".TextContent",
    "message": "Sí, lo tenemos en talla M.",
    "message_id_reply": "01A0C92D0C957FE98B73C8BA0CACF741",
    "integration_id_reply": "wamid.HBgNNTUxMTk5OTk5OTk5ORUCABEYEkIxRUE3ODJFREM1MjU2OTdDMQA=",
    "type": "TEXT"
  }
]
```

## Tipos de contenido

El campo que diferencia el tipo de mensaje es `@class`, dentro de cada elemento de `contents` o `attachments`, combinado con el campo `type`.

## Callbacks de estado

Los eventos de estado de un mensaje traen el tipo en `contents[0].type` (por ejemplo, `DeliveryCallback`, `MessageStatusCallback` o `ErrorCallback`) y el `_id` del mensaje al que se refieren. Usa el `_id` para vincular el estado con el mensaje. Cuando se encuentra el mensaje, los campos siguientes indican de qué mensaje es el estado y cómo leer el destinatario:

| Campo | Tipo | Descripción |
|---|---|---|
| `metadata.from_me` | boolean | Sentido del mensaje al que se refiere el estado: `true` cuando lo envió el negocio, `false` cuando se recibió del contacto. Es el mismo valor del webhook del mensaje |
| `recipient.identifier` | string | Destinatario informado por el canal. En WhatsApp Web, el estado de un mensaje enviado por el negocio puede informar el contacto como LID (identificador de WhatsApp que termina en `@lid`). En ese caso, el estado trae el `recipient.identifier` del mensaje: el teléfono del contacto (código de país + código de área + número) o el id del grupo. En los demás casos, llega el identificador que informó el canal |
| `metadata.from_api` | boolean | Viene del canal y puede ser `false` incluso en un mensaje enviado mediante la API. No uses este campo para filtrar estados |
| `contents[0].phone` | string | Identificador del contacto tal como el canal lo informó en el estado. Puede no ser el teléfono |

Usa `metadata.from_me` para saber el origen del mensaje y `recipient.identifier` para el destinatario. Si no se encuentra el mensaje, el estado llega con los valores que informó el canal.

Ejemplo de estado `RECEIVED` (mensaje entregado al contacto) en un canal WhatsApp Web, con el LID en `contents[0].phone` y el teléfono en `recipient.identifier`:

```json
{

    "_id": "019E6F1B0C2A7D4E8F1A2B3C4D5E6F70",
    "channel_id": "019E4C54B1B375A28970B605CA9B03C3",
    "metadata": {
      "@class": ".Metadata",
      "forwarded": false,
      "from_api": false,
      "from_me": true
    },
    "recipient": {
      "@class": ".Recipient",
      "identifier": "5511999990000",
      "name": ""
    },
    "contents": [
      {
        "@class": ".StateItem",
        "type": "MessageStatusCallback",
        "phone": "100000000000001@lid",
        "moment": 1779980476000,
        "state": { "@class": ".Received", "name": "RECEIVED" }
      }
```

## Resumen de los tipos

| `type` | Ubicación | Campo clave |
|---|---|---|
| `TEXT` | `contents[0]` | `message` |
| `IMAGE` | `attachments[0]` | `url`, `caption` (opcional), `thumbnail_url` |
| `AUDIO` | `attachments[0]` | `url` |
| `VIDEO` | `attachments[0]` | `url`, `caption` (opcional) |
| `STICKER` | `attachments[0]` | `url` (`.webp`) |
| `CONTACT_ARRAY` | `contents[0]` | `contacts[]` con `name`, `phones` |
| `INTERACTIVE_BUTTON` | `contents[0]` | `message`, `buttons[]`, `thumbnail` (si `mediaButtonType: "IMAGE"`) |
| `INTERACTIVE_ACTION` | `contents[0]` | `message`, `buttons[]` con `type: "URL"\|"CALL"`, `header`, `footer` |
