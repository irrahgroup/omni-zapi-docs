## Conceptos

Registra un nuevo endpoint de webhook en el canal. A partir de su creación, {projectName} empieza a enviar los eventos configurados a la URL indicada.

Un canal puede tener varios webhooks, algo útil para enviar eventos distintos a sistemas distintos o para mantener webhooks con formatos diferentes.

### Firma HMAC

Si `signing: true`, el campo `secret` se genera automáticamente y se devuelve **solo en esta respuesta**. Guárdalo de forma segura: no volverá a mostrarse en ninguna otra llamada.

Usa el `secret` para verificar en tu servidor la autenticidad de las peticiones recibidas. La firma llega en el header `x-webhook-signature` y se calcula sobre una cadena canónica de cinco campos, no solo sobre el cuerpo. Consulta [Firma HMAC](/es/webhooks/signature) para la cadena exacta y el código de validación.

### Validaciones

La petición se rechaza con `400`, sin guardar nada, en estos casos:

| Caso | Respuesta |
|---|---|
| `url` ausente o en blanco | `{"error": "URL is required"}` |
| `url` con formato no válido, o con un host que no resuelve solo a direcciones públicas | consulta [URL del webhook](/es/webhooks/introduction#url-del-webhook) |
| `events` ausente o vacío | `{"error": "At least one event is required"}` |
| Un elemento de `events` nulo, en blanco o con un nombre que no existe | `{"error": "events contains an unknown or empty event name"}` |
| `auth.type` `CUSTOM_HEADER` sin `auth.headerName` | `{"error": "Header name is required for CUSTOM_HEADER auth type"}` |
| Autenticación distinta de `NONE` sin la credencial de su tipo | `{"error": "Credentials are required when auth type is not NONE"}` |
| `payloadFormat` `CHATWOOT` sin `customAttributes.chatwoot_account_id` numérico mayor que cero | `{"error": "Chatwoot Account ID e obrigatorio (numero > 0) quando o formato e CHATWOOT"}` |
| `payloadFormat` `CHATWOOT` sin `customAttributes.chatwoot_inbox_id` numérico mayor que cero | `{"error": "Chatwoot Inbox ID e obrigatorio (numero > 0) quando o formato e CHATWOOT"}` |
| `payloadFormat` `CHATWOOT` con autenticación distinta de `API_KEY` | `{"error": "Formato CHATWOOT exige autenticacao API_KEY (selecione 'API Key' no tipo de autenticacao)"}` |

El nombre del evento se acepta en mayúsculas o minúsculas. La respuesta de nombre no válido no repite el valor enviado.

Los eventos también deben ser emitidos por el tipo del canal. Un evento fuera de la lista del tipo devuelve `422`, como en `{"error": "Events [PRESENCE_CHAT] are not supported by middleware META_WHATSAPP"}`. Consulta [Eventos por tipo de canal](/es/webhooks/channel-webhooks#eventos-por-tipo-de-canal). Un canal inexistente o de otro workspace devuelve `404` con `{"error": "Instance not found"}`.

### Formato `CHATWOOT`

Para entregar en Chatwoot, indica la cuenta y la bandeja de entrada en `customAttributes` y la API Key de Chatwoot en la autenticación `API_KEY`:

```json
{
  "url": "https://chatwoot.tuempresa.com/webhooks/omni-zapi",
  "events": ["MESSAGE_RECEIVED", "MESSAGE_STATUS"],
  "payloadFormat": "CHATWOOT",
  "customAttributes": { "chatwoot_account_id": 1, "chatwoot_inbox_id": 2 },
  "authType": "API_KEY",
  "key": "<api-key-de-chatwoot>"
}
```

`chatwoot_account_id` y `chatwoot_inbox_id` son números, no texto.

<Note>
  El `channelId` se obtiene a través del endpoint [Crear canal](/es/channels/create-channel).
</Note>
