## Un código, cinco canales

**No** escribes un flujo por canal. El SDK lee el tipo de canal y despacha el flujo correcto por su cuenta:

```javascript
import OmniZapi from '@omnizapi/connect';

const client = OmniZapi.newClient({ publicKey: 'SU_PUBLIC_KEY' });

// Idéntico para WhatsApp, Instagram, Messenger y Telegram; WhatsApp Web también necesita getQRCode
const response = await client.connect({ channelId: 'ID_DEL_CANAL' });

if (response.success) {
  await fetch('/mi-backend/conectar-canal', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(response),
  });
}
```

<Note>
  WhatsApp Web también necesita la función `getQRCode`, que obtiene el código QR desde tu backend. Los demás canales la ignoran, así que puedes pasarla siempre. Consulta [WhatsApp Web](/es/connect/whatsapp-web).
</Note>

El tipo viene del canal, no de la llamada. Defines el tipo en [Crear canal](/es/channels/create-channel) y el SDK resuelve el resto.

## Qué ocurre por dentro

<Steps>
  <Step title="El SDK consulta el canal">
    Llama a [`GET /instances/{channelId}/sdk-info`](/es/channels/sdk-info) para averiguar el tipo de canal, el app de Meta correspondiente y los [orígenes permitidos](/es/channels/sdk-info).
  </Step>
  <Step title="Despacha el flujo del tipo">
    Cada tipo tiene su propio camino de autorización: OAuth de Meta, código QR o token de bot.
  </Step>
  <Step title="Devuelve los datos de la conexión">
    El objeto devuelto cambia según el canal. Consulta la tabla de abajo.
  </Step>
  <Step title="Tú finalizas en el backend">
    Envía el resultado a tu backend y llama a la ruta de finalización del tipo de canal, con la Secret Key. Cada canal tiene su propia ruta: consulta la sección Finalizar la conexión en el backend, más abajo.
  </Step>
</Steps>

## Flujo de autorización por canal

|  | Meta Cloud API | WhatsApp Web | Instagram | Messenger | Telegram |
|---|---|---|---|---|---|
| **Cómo autoriza** | Embedded Signup de Meta | Código QR | OAuth de Instagram | OAuth de Facebook + elección de página | Token del bot |
| **Página** | [Meta WhatsApp](/es/connect/meta-whatsapp) | [WhatsApp Web](/es/connect/whatsapp-web) | [Instagram](/es/connect/instagram) | [Messenger](/es/connect/messenger) | [Telegram](/es/connect/telegram) |

## La respuesta cambia según el canal

Todos devuelven `success`, `channelId` y `type`, el tipo de canal. El resto depende del tipo:

| Campo | Meta Cloud API | WhatsApp Web | Instagram | Messenger | Telegram |
|---|:---:|:---:|:---:|:---:|:---:|
| `code` | ✅ | ❌ | ✅ | ✅ | ❌ |
| `wabaId` | ✅ | ❌ | ❌ | ❌ | ❌ |
| `phoneId` | ✅ | ❌ | ❌ | ❌ | ❌ |
| `coexistence` | ✅ | ❌ | ❌ | ❌ | ❌ |
| `redirectUri` | ❌ | ❌ | ✅ | ✅ | ❌ |
| `accessToken` | ❌ | ❌ | ✅ | ✅ | ❌ |
| `pageId` | ❌ | ❌ | ❌ | ✅ | ❌ |
| `botToken` | ❌ | ❌ | ❌ | ❌ | ✅ |

## Finalizar la conexión en el backend

Envía el objeto completo a tu backend. Allí, usa el campo `type` para elegir la ruta de finalización y arma el cuerpo a partir del resultado del SDK, siempre con la Secret Key:

|  | Meta Cloud API | WhatsApp Web | Instagram | Messenger | Telegram |
|---|---|---|---|---|---|
| **Ruta de finalización** | [`POST /v1/channels/{channelId}/connect`](/es/channels/connect-channel) | Sin finalización | [`POST /v1/channels/{channelId}/activate-instagram`](/es/channels/activate-instagram) | [`POST /v1/channels/{channelId}/activate-messenger`](/es/channels/activate-messenger) | [`POST /v1/channels/{channelId}/activate-telegram`](/es/channels/activate-telegram) |
| **Cuerpo, a partir del resultado del SDK** | `code`, `wabaId`, `phoneId` y `coexistence` | El canal se conecta cuando se escanea el código QR. Compruébalo con [`GET /v1/channels/{channelId}/zapi/status`](/es/channels/zapi-status) | `{"code", "redirectUri"}` | `{"pageId", "accessToken", "redirectUri"}`. La página y el `accessToken` vienen de [Listar páginas de Messenger](/es/channels/list-messenger-pages); consulta [Messenger](/es/connect/messenger) | `{"token": "<botToken del SDK>"}`. El campo se llama `token`, no `botToken` |

<Warning>
  `POST /v1/channels/{channelId}/connect` es solo de WhatsApp Oficial. Con el resultado de otro canal, responde `400` con `{"error":"wabaId is required"}`.
</Warning>

<Warning>
  La conexión solo funciona desde dominios autorizados, y el SDK falla en silencio cuando el origen no está en la lista. Lee [Orígenes del SDK](/es/channels/sdk-info) antes de integrar.
</Warning>

## Sin el SDK

El SDK existe porque cada canal tiene un flujo de autorización distinto en su plataforma de origen, y todos necesitan una ventana del navegador. Si tienes que montarlo a mano, cada página de canal describe la URL de autorización, los scopes y los parámetros usados.
