## Credenciales de la API

{projectName} funciona con un par de claves: **Public Key** y **Secret Key**. Ambas se generan en el menú **Seguridad** del panel: [Seguridad](https://app.omni.z-api.io/app/security).

---

## Public Key

La Public Key la utiliza el SDK de conexión de canales ([`@omnizapi/connect`](https://www.npmjs.com/package/@omnizapi/connect)). Con ella puedes [conectar canales](/es/channels/connect-channel) directamente desde tu sistema, sin necesidad de entrar al panel.

<Note>
  La Public Key se puede exponer en el frontend de tu aplicación, ya que sus permisos se limitan únicamente a la conexión de canales.
</Note>

Ejemplo de uso:

```javascript
import OmniZapi from '@omnizapi/connect';

const client = OmniZapi.newClient({
  publicKey: 'SU_PUBLIC_KEY'
});
```

---

## Secret Key

La Secret Key se utiliza para autenticarse en todas las APIs de {projectName}. Debe enviarse en el header `Authorization` como Bearer token en cada petición.

<Warning>
  La Secret Key **nunca** debe exponerse en el frontend. Úsala únicamente en el backend de tu aplicación.
</Warning>

Ejemplo de uso:

```bash
curl -X GET https://api.omni.z-api.io/whatsapp/businesses \
  -H "Authorization: Bearer SU_SECRET_KEY"
```

## Errores de autenticación

Esta sección vale para la **API Omni** (`https://api.omni.z-api.io/v1/...`). Cuando la Secret Key es rechazada, la API Omni responde `401` con el header `WWW-Authenticate: Bearer` y el cuerpo `{"error": "Authorization invalid", "message": <texto>}`. El `message` explica el motivo y qué hacer:

| Motivo | `message` |
|---|---|
| Header ausente o vacío | `Authorization invalid: the Authorization header is missing or empty. Send the workspace Secret Key as "Authorization: Bearer <secret-key>". See https://developer.omni.z-api.io/en/authentication` |
| Public Key (empieza con `pk_`) | `Authorization invalid: this is the Public Key, which only works in the channel connection SDK. Send the workspace Secret Key as "Authorization: Bearer <secret-key>". See https://developer.omni.z-api.io/en/authentication` |
| Fuera de formato (p. ej. el token del canal) | `Authorization invalid: the value sent is not a Secret Key. Send the workspace Secret Key, generated under Security in the panel, as "Authorization: Bearer <secret-key>". The channel token is not accepted here. See https://developer.omni.z-api.io/en/authentication` |
| Inexistente o revocada | `Authorization invalid: this Secret Key does not exist or is no longer valid. Copy the current Secret Key under Security in the panel and send it as "Authorization: Bearer <secret-key>". See https://developer.omni.z-api.io/en/authentication` |

`<secret-key>` es literal: la respuesta nunca repite el valor enviado. Trata el error por `error`; el `message` es para lectura y puede cambiar.

<Note>
  La Secret Key solo acepta el formato `^[a-z0-9_]+$`. El token del canal es hexadecimal en **mayúsculas**, así que, si se pega en lugar de la Secret Key, cae en **fuera de formato**. Un JWT de app OAuth (tres segmentos no vacíos separados por punto) se valida por el camino OAuth: si es válido, se acepta; si es inválido o expiró, la API responde `401` con `WWW-Authenticate: Bearer error="invalid_token"` y `{"error": "invalid_token"}`.
</Note>

<Note>
  Los `401` de arriba son de la **API Omni**. En la [ruta compatible Z-API](/es/z-api/introduction) (`/instances/{id}/token/{token}/...`) la autenticación **no cambió**: el rechazo viene como `{"error": "Authorization invalid"}`, sin `message` y sin `WWW-Authenticate` — `400` cuando el header está ausente o vacío y `422` cuando el formato es inválido o la clave no existe. El formato aceptado es el mismo (`^[a-z0-9_]+$`), así que el token del canal pegado en lugar de la Secret Key también se rechaza allí, con `422`.
</Note>

## Resumen

| Clave | Uso | Dónde usarla | ¿Se puede exponer en el frontend? |
|---|---|---|---|
| **Public Key** | [SDK de conexión de canales](/es/channels/connect-channel) | Frontend o backend | Sí |
| **Secret Key** | Todas las llamadas a la API ([canales](/es/channels/introduction), [plantillas](/es/templates/introduction), [mensajes](/es/messages/introduction)) | Solo backend | No |
